# SC-1 계약 규칙 — QA (2026-11-12)

슬롯 체스 계획서 §3(한 판을 끝까지 정의하기)의 「SC-1 한 판」: 계약전 순수 판정 + 계약을 아는 AI + 목표 HUD + 전용 저장·기록. [소라 릴](2026-11-12-pp1-reel.md) · [딱지·무대](2026-11-12-pp1-tags-stage.md)와 같은 **시험 스위치 `?lab=contract` 뒤에서만 돈다**(AI 판만). 스위치가 꺼진 기본 상태의 규칙·AI·정산은 그대로다.

**읽는 법과 걸리는 것**(계획서 §11 의 실패 신호와 견줌):
- AI 는 「무엇으로 지는지」 안다: 모르는 AI 를 58 대 2 로 이긴다. 판은 거의 전부(240판 중 230판) 계약으로 끝나고 48반수 상한에 닿는 판은 드물다.
- **보통 단계에서 백이 60~69% 이긴다.** 쉬움(44~48%)에서는 안 보이던 선공 편향이다. 계획서가 SC-0 의 실패 신호로 적은 「선공 편향을 줄이지 못함」에 해당할 수 있다 — 60판·30판 표본이라 확정은 아니다.
- **`pnr` 의 룩 목표는 30판 중 3~5판에서만 쓰였다.** 「세 번째 목표가 장식에 그침」 신호다. `pnb`·`pnr` 은 보통 단계에서 중앙 13반수로 너무 빨리 끝난다. 첫 후보 `p2nb` 는 19~20반수에 세 짝이 모두 쓰인다.
- 풀은 고치지 않았다. 이 수치는 SC-0(풀·색 편향 결정)의 입력이다.

## 찾은 것 · 고친 것

- **AI 가 계약을 알게 되자 딱지·무대 확인 스크립트의 국면이 깨졌다.** 내가 6.Qxf3 으로 비숍을 잡으면 AI 가 6…Qxa2 로 계약을 끝내 버린다(전에는 모르는 AI 라 그냥 뒀다). 「되돌리기」 「결승점」 항목을 폰을 아무도 안 잡은 줄(1.Nc3 d5 2.Nb5 Bd7 3.Nd4 e5 4.Nb3 Ba4 5.d3 Bxb3)로 옮겼고, AI 가 이기는 장면은 이 문서의 항목으로 남겼다.
- 내 단위 테스트의 국면 셋이 틀렸다(폰이 룩 길을 막음 · 비숍이 체크로 한 박자를 벌 수 있음 · 빈 칸으로 가는 수를 잡기로 셈). 국면과 기대를 고쳤다. AI 쪽 결함은 아니었다.
- 종료 때 위쪽 차례 글자가 길어 단추 줄을 두 줄로 밀었다 → 짧은 글(「백 계약 완성」)로, 자세한 줄은 배너에.
- HUD 머리의 「계약 2/3」이 진도처럼 읽혔다 → 「셋 중 둘을 먼저」.

## 재 보지 않았다 · 남은 것

- **사람 시험이 없다.** 계획서 SC-1 의 실패 신호 「목표 이해 실패」 「실제 길이 단축 없음」은 사람이 둬야 잰다. 봇 판 길이(중앙 19~20반수)만 쟀다.
- **소리를 듣지 못했다**(종료 소리는 기존 승·패·무승부 소리를 그대로 쓴다).
- **보상이 없다.** 계약전 결과는 전용 기록에만 남고 카드·도토리·마을 정산을 하지 않는다. 끝난 뒤의 결산 화면(React 결과 카드)도 뜨지 않고 배너만 뜬다. 보상 연결은 SC-2 다.
- 기권은 전용 기록에 패(`resign`)로 남는다. 배너 글은 일반 판의 것 그대로다(「이번 판 카드는 받았어요」 — 계약전에서는 사실이 아니다).
- 세로 화면에서 「지난 판을 이어서 둡니다」 알림이 잠깐 HUD 머리를 덮는다([캡처](2026-11-12-sc1-contract/hud-resume-touch.jpg)). 화면을 돌려도 HUD 배치는 판을 열 때의 것 그대로다.
- 상한(48반수)·스테일메이트·킹만 남음으로 끝나는 화면은 단위 테스트로만 확인했다(브라우저에서는 계약 종료만 나왔다). 릴보다 먼저 수를 두는 경우도 코드로만 맞췄다.
- 기물 부족 국면(킹+나이트 대 킹 등)에서 다시 접속하면 이어 하기가 버려진다(`replayResume` 이 chess.js 의 종료 판정을 쓴다). 48반수 안에 그런 국면이 나오는 일은 시뮬 240판에서 없었다.
- 친구 대전에는 넣지 않았다(같은 목표를 둘에게 보내는 일이 필요하다). 영어 문구도 없다.
- 실제 폰에서 보지 않았다.
