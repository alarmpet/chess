# 잡기 직후 드로우콜 줄이기 (2026-11-09)

STATUS DY 절의 열린 항목 「잡은 직후 드로우콜 최대(시그니처 전부터 105)」를 닫는다.

## 바꾼 것

- **말 받침 32개 → InstancedMesh 2개**([wizardChessEngine.js](../../src/wizardChessEngine.js) `pedestalInstanced` · `syncPedestals`). 받침은 진영마다 같은 지오메트리·같은 재질인데 말마다 한 번씩 그려졌다. 바닥 고리(`side-rings`)와 같은 방식으로, 매 프레임 각 말의 받침 행렬을 InstancedMesh 에 넣어 한 번에 그린다. 말 아래의 받침 메시는 높이·행렬만 주고 보이지 않는다. 그림자는 InstancedMesh 가 드리운다.
- **어지러운 별 3개 → InstancedMesh 1개**([impactFx.js](../../src/fx/impactFx.js)). 잡힌 말마다 별 메시 3개(3콜)였다. 이제 모든 별을 하나로 그린다(최대 8마리분).
- **드로우콜 게이트에 잡기 모드**([tools/drawcall_gate.mjs](../../tools/drawcall_gate.mjs)). 첫 국면 뒤에 [tools/fixtures/capture-lines.json](../../tools/fixtures/capture-lines.json) 의 세 잡기를 이어 하기로 세운다(폰끼리 exd5, 호랑이끼리 Qxe7+, 사자 Kxh1). 그 뒤 「두기 전 · 다가가며 · 타격 뒤 1.5초」의 최대를 같은 상한 100 으로 판정한다. `DRAWCALL_CAPTURE=0` 이면 건너뛴다.
- **잡기가 끝나지 않는 결함 막기.** 창 크기가 0×0 이면 카메라가 NaN 이 된다. 그러면 카메라 복귀 길이가 NaN 이 되고, `elapsed >= NaN` 이 영원히 거짓이라 연출이 끝나지 않는다(봇도 두지 않는다). 복귀 길이가 유한하지 않으면 0.22초를 쓴다. 디버그 API `debugMoveState()` 로 이것을 찾았다.

## 함정: ego 창 0×0

이번에 ego-browser 로 잰 값(대기 172~208, 잡기 +6~+13)은 **믿을 수 없다**. 그때 ego 창은 `innerWidth = innerHeight = 0` 이었다. 카메라 비율이 NaN 이면 절두체 컬링이 화면 밖 바다 장식까지 다 그린다. 같은 이유로 잡기 연출이 끝나지 않았다(위 결함). 측정 스크립트(`measure.mjs` · `breakdown.mjs` · `probe.mjs` · `hang.mjs`)와 그 결과 JSON 은 이 함정의 기록으로 남긴다. 드로우콜은 게이트(헤드리스, 정한 창 크기)로 잰다.

## 재 보지 않은 것

- 실제 GPU(휴대폰·PC 크롬)에서 프레임 시간이 줄었는지 재 보지 않았다. 드로우콜이 GPU 병목(체스 장면 21.6ms)에 얼마나 듣는지는 모른다.
- 다른 잡기 27칸의 최대는 재지 않았다(세 칸만 고정). 가장 많이 더하는 효과는 호랑이 발톱(3콜)·사자 고리(4콜)이고, 두 칸 모두 상한 안이다.
