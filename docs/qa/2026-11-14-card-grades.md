# 카드 등급 사다리 · 카드 보기 · 플레이 화면 4차 (2026-11-14)

사용자 요청: 「등급이 올라갈수록 딱 봐도 좋아 보이게」, 「수집한 카드를 도감처럼 볼 수 있게, 포켓몬·수집형 게임을 참고해서」.
조사: [docs/research/2026-11-14-fable-gamedev/findings.md](../research/2026-11-14-fable-gamedev/findings.md).

## 본 것(고치기 전)

- 등급은 넷(일반·고급·희귀·영웅)인데 **일반과 고급은 효과가 없고, 희귀의 무지갯빛은 마우스를 올려야만 보였다.** 폰에서는 영웅의 금빛 훑기 말고는 등급 차이가 그림 테두리뿐이었다.
- 도감은 있었다(작은 카드 24칸). **카드를 눌러도 크게 볼 수 없었다** — 누르면 마을 전시만 됐다.
- **폰(390px)에서 도감 격자가 화면보다 넓었다**(104px × 4칸 = 434px). 왼쪽이 잘리고 가로로 밀렸다. 확인 캡처에서 찾았다.

## 바꾼 것

GIF 가 아니라 코드(CSS)로 했다 — 그림 24장은 그대로, 손가락에 반응하고, 내려받는 양이 거의 안 는다.

| 등급 | 가만히 있을 때 | 카드 보기의 무대 |
| :-- | :-- | :-- |
| 일반 ★ | 효과 없음 | 어두운 무대 |
| 고급 ★★ | 은빛 후광 · 5초마다 스치는 흰 반짝임 | 은청색 |
| 희귀 ★★★ | 보랏빛 후광 · 스스로 흐르는 홀로그램 · 큰 카드는 좌우로 흔들림(5°) | 보라 + 천천히 도는 빛살 |
| 영웅 ★★★★ | 금빛 후광 · 금빛 훑기 · 둘레의 별 · 큰 카드는 크게 흔들림(11°) | 금빛 + 빠른 빛살 |

- **카드 보기**(`#card-inspect`): 도감의 가진 카드를 누르면 화면 가득 크게 뜬다. 등급 별(★), 이름, 보유 장수, 앞·뒤 카드 넘기기, 「마을에 전시」 단추. 카드를 문지르면 기울기와 빛이 따라온다. 마을 전시는 이 화면의 단추로 옮겼다.
- 도감 격자가 화면 폭에 맞게 줄어든다(폰에서 넘치지 않는다).
- 「효과 줄이기」(prefers-reduced-motion)에서는 움직임이 모두 멈추고 후광만 남는다.
- 작은 카드(도감 격자·마을)는 흔들리지 않는다 — 24장이 한꺼번에 흔들리면 어지럽다.

### 플레이 화면 4차(같은 날)

- 말 뒤에 가린 「갈 칸」 점이 말 몸 위로 옅게 비친다(깊이 비교를 뒤집은 인스턴스 메시 하나, 드로우콜 +1).
- 되감기·정찰 단추를 크림색 스킨으로.
- 화면 가장자리 비네트(CSS 한 겹, 번들 JS 0 · 드로우콜 0) — 조사에서 고른 「패스 하나짜리 후처리」의 대용.
- 체크메이트 고리를 화면에서 확인하는 항목 추가(1.f3 e5 2.g4 Qh4# 를 실제로 눌러 둔다).

## 찾은 것 · 고친 것

- 확인 스크립트가 심은 카드 저장이 비어 보였다 — 느린 PC 에서는 크롬이 뜬 지 1.2초 뒤에도 문서가 `about:blank` 라 `localStorage` 를 쓰지 못한다. 게임 문서가 뜬 것을 보고 심도록 고쳤다. **같은 방식으로 저장을 심는 다른 확인 스크립트(verify-play 등)도 같은 위험이 있다** — 고치지 않았다.
- 「효과 줄이기」에서도 빛 겹이 움직였다(선택자 우선순위) → `!important` 로 멈춘다.
- 도감을 연 직후에는 그림 24장이 늦게 뜬다(dev 서버 · 느린 PC 에서 수 초). 빌드에서는 재 보지 않았다.

## 재 보지 않았다 · 남은 것

- **사람 시험 없음.** 「딱 봐도 등급이 보이는가」는 내 캡처 판단뿐이다.
- 실제 폰(터치)에서 카드를 문질렀을 때의 기울기는 보지 않았다(마우스·헤드리스만).
- 카드가 날아오는 연출·판 끝 주머니 화면에서의 새 효과는 따로 보지 않았다(같은 `CardFace` 라 효과는 걸린다).
- 등급별 그림 자체(움직이는 그림, 입체 층)는 만들지 않았다. 카드 한 장이 여러 층으로 갈라져 움직이는 「진짜 입체」는 그림을 층별로 다시 만들어야 한다.
- 도감에 동물별 진행도·모은 순서·새 카드 표시 같은 수집 장치는 더하지 않았다.
- 플레이 화면: 화살표가 가장 가까운 점을 가리는 것, 가로 폰의 먼 줄 19px, 판 테두리·조명·말 그림은 그대로다.

# 캐릭터 룩 A · B (2026-11-14)

사용자 요청: 「캐릭터 룩도 더 업그레이드되면 좋겠다」 → A(화면에서 다듬기) → B(뒷모습 보강) 순서로.

## 본 것

- **내 말은 늘 뒷모습만 보인다.** 플레이어 쪽 말은 크림색 뒤통수와 등뿐이다. 얼굴이 보이는 쪽은 상대 말이다.
- 구운 색이 옅고 회색기가 돌아 카드 그림의 색감과 따로 논다.

## A — 넣었다

모델·텍스처는 그대로 두고 팩 재질의 셰이더에 두 가지를 얹었다(`applyAnimalLook`, 재질을 새로 만들지 않아 드로우콜·재질 수는 그대로).

- **채도 1.28배** — 텍스처 색의 채도를 올린다.
- **왕국색 윤곽** — 윤곽(시선과 비스듬한 면)이 왕국색으로 물든다. 백은 짙은 금빛, 흑은 밝은 보랏빛.
- 첫 시도는 빛을 **더하는** 테두리 빛이었다. 크림색 백 말이 하얗게 날아가 오히려 덩어리가 됐다 → 색을 **섞는** 방식으로 바꿨다(백은 윤곽이 짙어지고 흑은 밝아진다).
- 전후 비교는 `wizardChess.debugAnimalLook({ sat: 1, rim: 0 })` 로 끄고 켠다.

## B — 넣었다가 뺐다

- 말마다 등 뒤에 왕국색 방패를 달고 체스 기호(♟♞♝♜♛♚)를 그렸다(InstancedMesh 하나, 드로우콜 +1). 화면에서 32개가 뜨고 뒤에서 말 종류가 읽히는 것까지 확인했다.
- **사용자 판단: 없는 편이 낫다.** 코드에서 걷어냈다. 「뒷모습에서 말 종류가 약하게 읽힌다」는 문제는 그대로 남아 있다 — 다음에 풀 때는 표식을 덧붙이는 길이 아니라 모델 자체(등 쪽 무늬·망토·실루엣)로 가야 한다.

## 측정

- [verify-play.mjs](2026-11-13-play-screen/verify-play.mjs) 에 「캐릭터 룩」 항목을 더했다(네 화면): 채도 > 1 · 윤곽 > 0 · 드로우콜 ≤ 100. **dev 51/51**.
- 드로우콜 게이트(빌드, 안정화 20초): 첫 국면 **68**(넣기 전과 같다) · 잡기 세 칸 최대 75 / 74 / 58.
- 눈으로: 책상 화면에서 `debugAnimalLook` 으로 끄고 켜며 전후를 봤다. 폰 세로는 캡처(`2026-11-13-play-screen/after/phone-play.jpg`)로 봤다 — 흑 말의 보랏빛 윤곽은 보이고, 백 말 뒤통수의 금빛 윤곽은 폰 크기에서는 옅다.
- 게이트: 테스트 328/328 · tsc 오류 0 · 빌드 통과 · 첫 화면 JS gzip 395KB(상한 400) · CSS gzip 11KB.

## 재 보지 않았다 · 남은 것

- GPU 시간 전후는 재지 않았다(셰이더에 몇 줄이 늘었다. 11-11 기록으로 이 장면은 GPU 병목이다).
- 다른 팩(석상 등)에는 걸지 않았다 — 동물 리그에만 건다.
- 마을 화면의 주민은 다른 장면이라 이 효과가 없다.
- 사람 시험 없음.
