# FN-5 AI 를 작업자 스레드로 — 7단계 멈춤 고치기 — QA (2026-11-11)

[DR-M1 QA](2026-11-10-dr-m1.md) 에서 찾은 결함: 7단계(🦁 사자 왕, 3수 탐색)는 AI 가 화면과 같은 스레드에서 1~2초 생각해 그동안 화면이 멈췄다. STATUS FN-5 「탐색 작업자 스레드」를 이번에 했다.

## 바꾼 것

| 곳 | 내용 |
| :-- | :-- |
| `src/rules/aiWorker.js`(새) | `{ id, fen, opts }` 를 받아 같은 `chooseMove` 로 고른 수를 돌려주는 Web Worker |
| `src/wizardChessEngine.js` | AI 차례(`triggerAIMoveNow`)가 작업자에게 묻는다. 묻는 동안 `aiThinking` 이 입력을 막는다(예전 `aiTimer` 와 같은 자리). **답은 판 번호·국면(FEN)·차례가 물을 때와 같을 때만** 둔다. 판을 바꾸는 곳 7군데(새 판·되돌리기·기권·장면 설정 등, `clearTimeout(aiTimer)` 자리)가 `dropAiThought()` 로 늦은 답을 버린다. 작업자를 못 쓰면(없거나 오류) 예전처럼 화면 스레드에서 생각한다. `?aisync=1` 은 비교용으로 예전 방식. 손과 뇌·대본 넘기기의 동기 `chooseSmartAIMove` 는 그대로 |
| `debugBusy` | AI 가 생각하는 동안도 「바쁨」(시험 도구가 그동안 수를 넣지 않게). `debugAiWorker()` = worker · sync |

빌드: 작업자는 따로 받는 조각(`aiWorker-*.js` 39KB, chess.js 포함). 첫 화면 JS 382KB 그대로, 늦게 받는 JS 20 → 33KB(gzip, 전체 상한 600).

## 측정 ([verify-worker.mjs](2026-11-11-fn5/verify-worker.mjs), 7단계 고정, 내 수 8번, 같은 조건 두 번)

| | 예전(`?aisync=1`, 화면 스레드) | 지금(작업자 스레드) |
| :-- | --: | --: |
| AI 가 생각하는 동안 **가장 긴 「긴 작업」**(화면 스레드를 50ms 넘게 붙든 일) | **632ms**(중앙값 290) | **0 — 한 번도 없음** |
| 그동안 **가장 긴 프레임 간격** | **618ms**(중앙값 285) | **49ms**(중앙값 42) |
| AI 생각 시간 중앙값 · 가장 김 | 518 · 884ms | 677 · 1,723ms |
| 둔 수 모두 합법 | 예 | 예 |

[result-worker.json](2026-11-11-fn5/result-worker.json). 첫 측정(같은 스크립트)에서는 예전 방식이 1,080ms 까지 멈췄다 — AI 가 무작위라 국면이 매번 달라서다. 생각 시간 자체는 줄지 않는다(작업자로 옮긴 것일 뿐, 길면 1.7초). **그동안 화면이 돈다**는 것이 바뀐 점이다. 프레임 간격 42ms 는 헤드리스 창의 rAF 간격이다(메모: 이 PC 의 창은 rAF 가 24~29Hz).
