## 절차 (`chess-character-pipeline` 스킬)

1. **콘셉트** — Flow Nano Banana 2.1, 1:1. 각 건물의 **옛 콘셉트를 참조로 올리고** 「같은 모양·크기·시점, 재료만 진주빛 돌·청록 지붕·금 띠·조개·산호로」 다시 그렸다. 그래서 크기·자리가 옛 모델과 맞아 `LOOKS` 를 거의 고치지 않았다. 이미지 생성은 크레딧 0. 시트: [concepts](2026-11-05-at7-concepts.jpg).
2. **워터마크** — `tools/clean_concept.py`(새 도구): (921,921) 반지름 40 을 `cv2.inpaint` TELEA 로 메움.
3. **모델** — 로컬 TRELLIS → `keepuv_low`(12,000면 · 텍스처 768). `tools/make_building.py` 에 `--tag` 를 더해 `.reports/town-atl/` 에서 새로 만들었다(예전 raw 를 재사용하지 않게). 렌더: [renders](2026-11-05-at7-renders.jpg).
4. **코드 조정** — 물레방아: 바퀴가 모델에 있어 예전 풍차 날개(`makeSails`)를 빼고 거품 줄기로. 발전소: TRELLIS 가 유리 돔을 불투명 청록으로 구워 예전처럼 받침 위를 셰이더로 잘라내고 코드 유리 돔을 얹었다. 자르는 높이 `DOME_CUT` 0.3 → 0.36(새 받침 높이).

## 겪은 문제와 다음에 피할 것

- **TRELLIS 서버가 HuggingFace 온라인 확인에서 멈췄다**(443 연결만 열고 디스크 0.09GB). `HF_HUB_OFFLINE=1` 로 띄우면 5분 안에 떴다 → `.reports/town-atl/start_trellis.ps1`. 스킬의 `trellis_up.ps1` 에도 넣을 만하다(스킬 파일은 고치지 않았다).
- **배치 두 개가 동시에 돌아 GPU 8GB 가 넘쳤다**(CUDA OOM, 서버 작업자가 망가져 뒤 요청이 0초에 실패). 원인: 백그라운드 명령 제한으로 끝난 줄 안 첫 배치가 살아 있었다. 이후 배치는 `nohup` 하나만, 항목마다 서버 응답을 보고 죽었으면 다시 띄우게 바꿨다.
- **물레방아 디코딩 중 서버가 한 번 죽었다.** 다시 띄워 맨 뒤에 돌리니 됐다(원인 미확인).
- **Flow 「새 타일 수」 판정이 8에서 막혔다** — 목록이 8칸까지만 그려진다. 같은 프로젝트에서 다운로드 버튼으로 받아 이름(`atl-*.jpg` 업로드와 생성물)으로 짝지었고, 3라운드는 「처음에 없던 타일이 생겼나」로 판정하게 고쳤다.
- TRELLIS 서버는 작업 뒤에도 켜져 있다(GPU 약 2GB).
