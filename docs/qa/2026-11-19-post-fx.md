## 측정

**GPU 시간** — 크롬을 그래픽 카드(ANGLE D3D11, Intel UHD 0xA788)로 띄워 엔진의 GPU 타이머로 4초씩, 세 회차(상태 순서를 회차마다 돌림). `measure-post.mjs` · `result-measure.json`.

| | 끔 | 켬 · FXAA (기본) | 켬 · MSAA 4배 |
| :--- | ---: | ---: | ---: |
| 데스크 1280×800 | 25.6ms | **22.5ms** | 31.1ms |
| 폰 390×844 ×2 | 25.0ms | **23.4ms** | 30.7ms |

켠 쪽이 매 회차 더 빠르다. 끈 상태는 장면 전체를 MSAA 캔버스에 그리고, 켠 상태는 MSAA 없이 반정밀 텍스처에 그린 뒤 FXAA 로 마무리하기 때문이다. MSAA 렌더 타깃은 비싸서 기본에서 뺐다(첫 측정에서 데스크 21.7 → 38.0ms).
(처음 세기로 잰 첫 측정: 데스크 23.3 → 20.8ms · 폰 24.3 → 22.8ms. 세기를 올려도 비용은 그대로다 — 표본 수가 같다.)

**드로우콜** — 화면 사각형 하나만 늘어난다. 게이트(SwiftShader, 빌드본): 초기 69 → **70** · 잡기 최대 77 → **78** · 계약전 첫 화면 **74**(상한 100).

**블라인드 비평** — 코드와 설정을 모르는 에이전트에게 끈 것과 켠 것을 A/B 로 섞어 주었다(정답은 `blind/`).

## 만들다 고친 것

1. **구석 그늘이 털 위에 자글자글한 점**으로 나왔다 — 표본 방향을 픽셀마다 돌린 탓(흐리기 패스가 없다). 방향을 고정했다. `tune/` 의 확대 비교.
2. **빛 번짐이 크림색 판 칸까지 번져 뿌옇다** — 문턱 0.9 → 1.5(톤매핑 전 선형). 평소 화면에서는 거의 안 보이고 보석·잡기 효과처럼 정말 밝은 것에 걸린다.
3. **드로우콜이 잡기 순간 77 → 114 로 보였다** — 내가 셈을 프레임 단위로 비우게 바꾸면서 three 가 원래 빼는 그림자 패스(37콜)가 섞였다. 셈은 원래대로 두고 보정 사각형만 장면 셈에 더한다. 실제 증가는 +1 이었다.
4. 처음 세기는 블라인드에서 데스크를 구별하지 못했다 → 세 단계(지금 · 중간 · 강함)를 나란히 찍어 중간으로 올렸다(`tune/grid-off-now-mid-strong.jpg`: 왼쪽 위 끔 · 오른쪽 위 처음 · 왼쪽 아래 지금 · 오른쪽 아래 강함).

## 알고 넘어간 것

1. **「와우」는 아니다.** 나란히 놓아야 알 수 있는 다듬기다. 계획서의 큰 한 방(물과 빛 · 판의 시간 · 밀물)은 이 위에 얹는다 — 이제 깊이 텍스처가 있어 물속 빛·물결 연출을 같은 패스에 넣을 수 있다.
2. 공기 원근(멀수록 하늘색)은 넣지 않았다. 장면에 이미 안개(`FogExp2`)가 있다.
3. 블룸은 평소 화면에서 거의 안 보인다. 왕관 보석·잡기 섬광에서 얼마나 보이는지는 따로 찍지 않았다.
4. 마을(섬) 화면은 렌더러가 따로라 보정이 걸리지 않는다.
5. 계층 렌더 실험(`?layers=1`)이 켜져 있으면 보정은 꺼진다.
6. 실제 폰(외장 기기) · 외장 그래픽에서는 재 보지 않았다. 측정은 이 PC 의 내장 그래픽뿐이다.
7. 예전 설정을 저장한 브라우저도 `post` 키가 없으므로 켜진 채로 시작한다.
