# LA-R R-2 — 두 사람 서명 · 서버 다시 두기 · Glicko-2 (2026-11-09)

계획서: [Play 출시 교훈 적용](../plans/2026-11-09-play-launch-lessons-plan.md) §4.2 R-2. 앞 단계: [R-1](2026-11-09-ranked-r1.md).

## 흐름

1. 랭크 판이 끝나면 두 화면이 각자 같은 판 기록에 자기 기기 키로 서명해 `POST /api/rank/result` 로 보낸다.
   - 판 기록: 방 · 판 번호 · 백/흑 id · 수 목록 · 결과 · 이유
2. 서버(`worker/index.js`)는 보고서를 하나씩 검사한다.
   - 형식
   - id 가 공개 키 해시와 같은지
   - 서명
   - chess.js 로 처음부터 다시 둔 결과가 보고와 같은지(`src/rank/report.js`)
3. 첫 보고서는 `waiting` 으로 저장한다.
4. 둘째 보고서가 오면 두 글이 같은지, 서명한 사람이 서로 다른지 본다.
   - 맞으면 Glicko-2 로 두 사람을 갱신하고, 판을 `matches` 에 한 번만 넣는다.
   - 다르면 `mismatch` 로 답하고 점수는 그대로 둔다.
5. 화면은 `waiting` 이면 2.5초 간격으로 최대 8번 다시 보낸다. 같은 보고서라 두 번 세지 않는다.
   - 결과는 방 막대에 「🏆 1500 → 1662 (+162)」 로 보인다.

## 배포 전에 사람이 할 일 (하지 않았다)

Cloudflare 계정에 D1 을 만드는 것은 계정을 바꾸는 일이라 하지 않았다. 지금 `wrangler.jsonc` 그대로 배포하면 database_id 가 없어서 실패한다.

```bash
npx wrangler@4 d1 create wildcrown-rank
```

나온 `database_id` 를 `wrangler.jsonc` 에 넣은 뒤:

```bash
npx wrangler@4 d1 migrations apply wildcrown-rank --remote
```

## 재 보지 않았다 · 남은 것

- **짜고 치기:** 둘이 짜고 같은 거짓 판에 서명하면 막지 못한다. 같은 상대 상한·시간 대조는 R-4 에서 한다.
- **도중 이탈:** 판 도중 나가거나 연결이 끊기면 보고가 없어 점수가 그대로다. 몰수는 R-4 에서 한다.
- **보고가 하나만 온 판:** `reports` 에 남는다. 지우는 크론은 없다.
- **쉬는 기간:** 판 사이 쉬는 기간의 RD 증가(Glicko-2 6단계)를 아직 넣지 않았다.
- **lichess 방식과의 일치:** 「한 판 = 평가 기간」이 lichess 와 같은지는 그쪽 코드로 확인하지 않았다(AGPL).
- **실제 Cloudflare:** D1 동시성(같은 판이 동시에 두 번)은 로컬에서만 봤다.
- **화면:** 뱃지 표시와 내 점수 보기는 R-3 에서 한다. 휴대폰 폭은 재 보지 않았다.
- **번들:** 여유가 10KB 다. chess.js 는 원래 들어 있었고, 새로 늘어난 몫은 재 보지 않았다.
