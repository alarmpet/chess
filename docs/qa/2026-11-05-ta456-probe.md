## perf_probe 「안정」 기준 재조정 (`tools/perf_probe.mjs`)
빌드(`dist/`)를 `vite preview` 4173 에서 3회 연속(`docs/perf/2026-11-04-probe.log`, 날짜는 UTC) + 전날 `gate-s3`:

| 실행 | 로드별 콜백 JS 중앙값(ms) | 바닥 | 최대 | rAF |
| :-- | :-- | --: | --: | --: |
| gate-s3 (11-04) | 1.4 / 2.2 / 1.1 | 1.1 | 2.2 | 41.6 |
| probe 1 | 1.1 / 2.1 / 2.1 | 1.1 | 2.1 | 41.7 |
| probe 2 | 2.9 / 2.2 / 1.8 | 1.8 | 2.9 | 41.7 |
| probe 3 | 2.9 / 1.6 / 1.4 | 1.4 | 2.9 | 41.7 |

- **로드 안** 표본 셋의 범위는 0.5ms 이하(예: 1.0/1.1/1.2, 2.9/3.1/2.9) — 측정 자체는 안정.
- **로드끼리**는 1.1~2.9ms 로 갈린다. 같은 빌드·같은 서버이므로 환경(그 순간의 프로세스·GPU 상태). 범위 0.5ms 기준은 4회 중 0회 통과 → 기준이 잘못됐다.
- 바꾼 판정: ① **상한** 로드 최대 중앙값 ≤ 5ms(`withinCap`) ② **비교값** 로드 최소(`floorMs`, 4회 바닥 1.1~1.8 범위 0.7) — 빌드끼리 바닥이 **1ms 넘게** 벌어질 때만 차이로 센다. `stable` 필드는 없앴다.
- 드로우콜은 4회 모두 98. 빈 페이지 rAF 41.7(24Hz) 로 어제의 34.8(29Hz) 과 다름 — 환경이 날마다 흔들린다는 증거 하나 더.
