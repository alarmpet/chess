# 실험 ① — 갱신 빈도별 계층(캔버스) 분리, 전후 GPU 시간 (2026-11-05)

사용자 요청: 「UI 가 얼마나 자주 바뀌는지에 따라 캔버스를 나누고 전후 성능 비교」. 구현은 `src/fx/layeredRender.js`, 엔진 배선은 `src/wizardChessEngine.js`(`layered.render()`, `wizardChess.setLayered(on, hz)`, `?layers=1&hz=6`). **기본은 꺼져 있다** — 켤지는 사용자 결정(STATUS §3).

## 무엇을 나눴나

| 층 | 들어가는 것 | 그리는 때 |
| :-- | :-- | :-- |
| 정적(층 1) | 바다·섬·모래섬·산호·물고기(`biomeGroup`), 보드 타일·테두리(`boardGroup`), 대성당(`cathedral`) | 카메라가 움직였을 때, 팩·팔레트·모델 로드 뒤, 그리고 `hz` 마다(바다 애니메이션용) — 오프스크린 렌더 타깃(HalfFloat, MSAA 4) |
| 동적(층 0) | 말·받침·바닥 링·접촉 그림자·하이라이트·타격 효과·화로 스프라이트 | 매 프레임, 정적 타깃을 화면에 깐 뒤 깊이만 지우고 그 위에 |

DOM 캔버스를 둘로 나누지 않고 한 WebGL 컨텍스트 안에서 나눴다. 두 캔버스는 PMREM 환경맵·텍스처를 컨텍스트마다 다시 올려야 하고 위 캔버스가 포인터를 가로채며, 효과는 같다. 톤매핑·sRGB 는 화면에 올리는 셰이더에서 한다(`OutputPass` 방식).

## 측정 방법

`EXT_disjoint_timer_query_webgl2` 로 프레임의 렌더 호출 전부(정적 패스 + 합성 + 동적 패스)를 감싼 GPU ms. 같은 페이지에서 모드만 바꿔 4초씩, 기본(플레이어) 카메라, 초기 국면, Claude 내장 브라우저 1024×768 dpr 1, Intel UHD. 표본 n = 80~107.

## 결과 — 가만히 있을 때(판 기다리는 대부분의 시간)

| 모드 | 정적 재렌더/초 | GPU ms 중앙값 | p95 | 드로우콜(마지막 패스) |
| :-- | --: | --: | --: | --: |
| **끔(지금)** | 매 프레임 | **20.6** | 26.9 | 95 |
| 끔(다시 잼) | 매 프레임 | 20.3 | 26.6 | 95 |
| 계층 hz 12 | 약 9.5 | 18.5 | 28.8 | 67 |
| 계층 hz 6 | 약 5.5 | **12.0** | 28.3 | 67 |
| 계층 hz 3 | 약 2.8 | 11.8 | 24.6 | 67 |
| 계층 hz 0(카메라 움직일 때만) | 0 | **11.8** | 21.6 | 67 |

## 결과 — 수를 두는 동안(e2e4 / d2d4 + AI 응수, 3초 창)

| 모드 | GPU ms 중앙값 | p95 |
| :-- | --: | --: |
| 끔 | 22.6 | 32.3 |
| 계층 hz 6 | **15.8** | 31.2 |

- 가만히 있을 때 **20.6 → 11.8~12.0ms(−42%)**, 수를 둘 때 22.6 → 15.8ms(−30%). hz 12 는 거의 이득이 없다(프레임이 약 25/초라 절반 가까이 정적을 다시 그린다).
- 남은 11.8ms 는 거의 전부 말 32개(스킨드 20,000tri × 32)의 몫이다 — 다음 병목.
- 드로우콜 95 → 67 은 동적 패스만 센 값이다. `debugRenderCalls` 가 마지막 `render()` 의 수를 돌려주므로, 계층 모드에서는 게이트가 정적 패스를 못 센다(기본이 꺼짐이라 게이트는 그대로).
- fps 는 이 PC 의 rAF 환경값(약 25~29Hz)이라 어느 모드도 안 바뀐다. 다른 PC·휴대폰에서는 재 보지 않았다.

캡처: [계층 hz 12, 기본 카메라](2026-11-05-layered-hz12.jpg) — 끔과 눈으로 같다(픽셀 비교 안 함). 위 카메라로 바꾼 뒤에도 정적 층이 새로 그려지는 것을 봤다. 콘솔 오류 0.

## 보이는 차이(켜면)

1. 바다·거품 애니메이션이 `hz` 로 떨어진다. hz 6 은 물결이 뚝뚝 끊겨 보일 수 있다(사람이 보지 않았다).
2. 정적 패스는 그림자 맵을 갱신하지 않아 섬의 나무·흙이 스스로 드리우던 그림자가 사라진다. 말 그림자는 동적 패스의 맵을 정적 패스가 다음에 쓸 때 보드에 찍히므로 최대 1/hz 늦다(hz 6 → 170ms).
3. 동적 물체는 늘 정적 물체 위에 그려진다. 체스판에서는 말이 보드 위라 차이가 없고, 대성당 팩에서 기둥 뒤로 카메라를 돌릴 때만 말이 기둥을 뚫고 보인다.
4. 메모리: 화면 크기 HalfFloat MSAA 타깃 하나.

## 추천

- **켠다, hz 6.** 가만히 있을 때 GPU 가 42% 줄고 Intel UHD 에서 16.7ms(60fps 상한) 아래로 들어온다. 물결이 끊겨 보이면 바다 셰이더의 시간을 정적 재렌더 때만 흘리는 대신 **바다만 동적 층**으로 옮기는 변형을 잰다(바다는 1쿼드라 싸다).
- 말 그림자의 170ms 지연은 「수를 두는 동안(`isAnimatingMove`)에는 매 프레임 정적을 다시 그린다」로 없앨 수 있다 — 수를 두는 동안 이득은 줄지만 가만히 있을 때 이득은 그대로. 사용자가 켜기로 하면 이 변형부터.
- 다음 병목은 말이다: 11.8ms 가운데 대부분. 폰 8 스킨드 인스턴싱(엔진 선택 계획 7~10일차, 생략했던 것)·LOD 가 다음 실험.
