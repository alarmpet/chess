# 타격 1 — 사건 꾸러미 · 화면 번쩍임 · 겹친 타격 불빛 (2026-11-15)

계획: [그래픽 업그레이드 계획](../plans/2026-11-15-graphics-upgrade-plan.md) GX-1 · GX-2 · GX-3.

## 넣은 것

- **GX-1 사건 꾸러미 표**(`src/fx/impactTier.js` 의 `EVENT_FX`): 캐슬링·승급·체크·체크메이트가 내는 별 뭉치·바닥 고리·낱말·화면 번쩍임·겹친 불빛이 표 한 줄이다. 엔진은 `playEvent(kind, 자리, 둔 쪽)` 하나로 낸다(전에는 네 군데에 값이 흩어져 있었다). 잡기는 원래의 세 단계 표를 그대로 쓴다.
  - **소리는 표에 넣지 못했다.** 사건마다 고르는 조건이 달라(이겼나 졌나, 연속인가) 엔진에 남겼다.
- **GX-2 화면 번쩍임**(`#hit-flash`, CSS 한 겹): 화면 가장자리가 사건의 색으로 한 번 물든다.

  | 사건 | 색 | 세기 | 길이 |
  | :-- | :-- | :-- | :-- |
  | 작은 잡기(폰끼리) | 없음 | — | — |
  | 중간 잡기 | 내가 잡으면 금빛 · 내 말이 잡히면 붉은빛 | 0.16 | 200ms |
  | 큰 잡기 | 같음 | 0.30 | 320ms |
  | 체크 | 주황 | 0.20 | 260ms |
  | 승급 | 금빛/붉은빛 | 0.26 | 320ms |
  | 체크메이트 | 금빛/붉은빛 | 0.42 | 520ms |

  - 설정의 「화면 흔들림」을 끄거나 기기의 「효과 줄이기」가 켜져 있으면 번쩍임도 없다.
  - 구경·둘이 두기처럼 편이 없으면 금빛이다.
- **GX-3 겹친 타격 불빛**(`src/fx/hitGlow.js`, 늦게 받는 묶음): 맞은 자리에 흰 심(0.1초) → 때린 쪽 왕국색 네 갈래 별(0.24초) → 때린 방향으로 튀는 불똥(중간 8개 · 큰 것 16개 · 작은 잡기는 없음). InstancedMesh 하나, 텍스처 없음(모양은 셰이더가 그린다), 더하기 합성.

## 바로잡은 것

계획서 초판에 「맞은 말이 하얗게 번쩍이지 않는다」고 적었는데 **틀렸다.** 이미 있었다(`impactFx.flash`, 0.16초). 착수하며 코드에서 확인하고 계획서를 고쳤다. GX-2 는 화면 번쩍임만 넣었다.

## 찾은 것

- 확인 스크립트가 **앞 판을 심은 판으로 착각**했다(수 개수만 봤다). 심은 수순과 대조하도록 고쳤다. 어제 고친 여섯 스크립트도 수 개수만 본다 — 같은 틈이 있을 수 있다(고치지 않았다).
- 느린 PC 에서 첫 누르기가 안 먹을 때가 있어, 기보가 안 늘면 다시 누르게 했다.
- **폰 세로에서 큰 낱말(「역전!」)이 화면 오른쪽 밖으로 잘린다**(`after/phone-big.jpg`). 이번 변경 전부터 있던 것으로 보인다(낱말은 맞은 자리 옆에 뜬다) — 고치지 않았다.

## 재 보지 않았다 · 남은 것

- **사람 눈으로 제 속도에서 본 적이 없다.** 느리게 찍은 캡처와 숫자뿐이다. 화면 번쩍임은 가장자리만 옅게 물들어 캡처에서는 거의 안 보인다 — 실제로 느껴지는지, 거슬리는지는 모른다.
- GPU 시간 전후는 재지 않았다(더하기 합성 조각 최대 18개).
- 실제 폰.
- 소리는 그대로다. 사건 표에 소리를 넣는 일, 승급·체크메이트에서 불빛의 방향(지금은 사방)은 남았다.
- 첫 화면 묶음을 줄이는 일(효과 코드를 늦게 받는 쪽으로 옮기기)은 하지 않았다. 불빛은 처음부터 늦게 받는 묶음에 넣었다.
