# 사람 시험 A·B 를 LLM 세 모델로 대신하기 (2026-11-09)

사용자 지시: 「사람이 해야 할 일, LLM 들을 활용해서 최대한 사람이 하듯 직접 진행해」.
계획서: [잡기 맞대결 계획서](../plans/2026-11-08-capture-matchup-plan.md) 7절(사람 시험 A) · CX-6(사람 시험 B).

**주의: 사람 시험이 아니다.** 시험을 푼 것은 agy · grok · codex(gpt-6-sol) 세 모델이고, 영상 대신 0.25초 간격 12컷 그림을 봤다.
사람 시험 A·B 는 여전히 열려 있다. 이 기록은 사람 시험 전에 무엇을 고칠지 고르는 대역이다.

- 세 모델은 읽기 전용으로 돌렸다.
  - agy: `--mode plan`
  - grok: `--permission-mode dontAsk`, 웹 검색 끔
  - codex: `-s read-only`
  - 권한을 모두 여는 플래그는 권한 분류기가 막아 쓰지 않았다.
- 시험 A 의 그림 파일 이름은 `q01~q30` 으로 익명화하고 시드로 섞었다. 정답은 `answer-key.json` 이다.
- 모델 로그에서 폴더 밖(정답 파일·저장소)을 연 흔적은 찾지 못했다(`grep answer-key|D:/chess|cx0-captures` 결과 0건).

## 시험 A — 소리·글자 없이 「누가 잡았나·누가 잡혔나」

입력:
- 「전」: CX-0 기준 영상(`*-before.mp4`)
- 「후」: 지금 모습을 글자를 끄고 찍은 영상(`*-quiz.mp4`)

| 묶음 | 모델 | 잡은 동물 | 잡힌 동물 | 둘 다 | 모름 |
| :-- | :-- | --: | --: | --: | --: |
| 전 | agy | 20/30 | 19/30 | 13/30 | 0 |
| 전 | grok | 13/30 | 16/30 | 7/30 | 0 |
| 전 | codex | 22/30 | 14/30 | 13/30 | 0 |
| 후 | agy | 13/30 | 17/30 | 11/30 | 0 |
| 후 | grok | 11/30 | 10/30 | 6/30 | 7 |
| 후 | codex | 23/30 | 22/30 | **18/30** | 0 |
| **합(세 모델)** | 전 | 55/90 | 49/90 | 33/90 | |
| | 후 | 47/90 | 49/90 | 35/90 | |

**전과 후는 같은 조건이 아니다.** 「전」 영상에는 글자가 들어 있다. 시그니처 글자(샤악!·어흥! 등)가 잡은 동물을 알려 준다. agy 의 「전」 답 근거에 「발톱(샤악!)」 「포효(어흥!)」가 그대로 나온다. 그래서 「잡은 동물」이 55→47 로 내려간 것을 「나빠졌다」로 읽으면 안 된다. 잡힌 쪽(글자와 무관)은 49→49 로 같다.

모델 차이가 크다. 「둘 다」가 codex 18, agy 11, grok 6 이다. 사람 세 명의 편차를 대신 보여 주는지는 알 수 없다.

「후」에서 세 모델이 함께 틀린 것(`score-a.json`):

| 무엇 | 틀린 수 |
| :-- | --: |
| 잡힌 판다 → 미어캣으로 봄 | 8 |
| 잡힌 호랑이 → 미어캣으로 봄 | 7 |
| 잡힌 캥거루 → 미어캣 4 · 코뿔소 4 | 8 |
| 잡힌 코뿔소 → 미어캣으로 봄 | 4 |
| 잡은 코뿔소 → 캥거루로 봄 | 6 |
| 잡은 호랑이 → 판다로 봄 | 5 |

잡힌 쪽은 날아가거나 구르는 동안 작아서 「미어캣」으로 읽히는 일이 가장 많다. 이것이 12컷 그림의 한계인지, 실제 영상에서도 그런지는 재 보지 않았다.

## 시험 B — 스물한 판 두고 「지겹다·느리다」

1. 헤드리스 Chrome 에서 봇이 양쪽을 두게 했다(`play20.mjs`). 사람 쪽 수도 같은 AI(`triggerAIMoveNow`)로 두었다.
   - 판당 최대 160수, 실제 속도.
   - 두 묶음을 나란히 돌려 21판을 얻었다. 16판은 끝까지 갔고, 5판은 160수 제한에 걸렸다.
2. 잡기마다 다음을 남겼다(`play20/*.ndjson`, `score-b.json`):
   - 조합
   - 엔진이 정한 연출 길이(`moveClock.total`)
   - 벽시계 시간
   - 역전·거울·콤보·포효 여부
3. 세 모델에게 다음 세 가지를 주고 「이 판들을 둔 사람」으로서 지겨운 조합 5개·느린 조합 5개·고칠 것을 고르게 했다(`answers-b/`).
   - 판별 잡기 일지(`diary.md`)

   - 조합마다 지금 모습(글자 있음) 12컷 그림

### 세 모델의 판정과 대조

| 판정 | agy | grok | codex | 통합자(답을 읽기 전에 씀, `r-claude-b.md`) |
| :-- | :-- | :-- | :-- | :-- |
| 지겨움 | 미어캣→미어캣, 코뿔소→미어캣, 캥거루→미어캣, 판다→미어캣, 미어캣→판다 | 미어캣→미어캣, 캥거루→미어캣, 코뿔소→미어캣, 판다→미어캣, 캥거루→캥거루 | 미어캣→미어캣, 코뿔소→미어캣, 캥거루→미어캣, 판다→미어캣, 미어캣→판다 | 「→미어캣」 묶음 |
| 느림 | 룩→퀸, 룩→룩, 비숍→룩, 비숍→퀸, 퀸→퀸 | 룩→룩, 룩→퀸, 비숍→룩, 퀸→퀸, 비숍→퀸 | 룩→룩, 퀸→퀸, 나이트→나이트, 비숍→룩, 룩→퀸 | 룩→퀸, 룩→룩 |
| 잡기가 전체로 긴가 | 예 | 아니오 | 예 | 아니오(TA-8 재현 안 됨) |

- **지겨움은 넷이 같은 곳을 짚었다:** 「무엇이 미어캣을 잡는다」. 세 모델 모두 「잡힌 미어캣의 끝 장면이 매번 같다」를 근거로 댔다.
- **느림은 룩→룩·룩→퀸이 공통이다.** 다만 셋 다 룩→퀸(7번, 모두 역전)과 비숍→퀸은 「드문 장면이라 그대로 두기」를 골랐다.

버린 주장(저장소에서 확인):
- **agy·grok:** 「미어캣 잡기를 되풀이할 때 카메라 이동·줌을 빼자」 → **전제가 틀렸다.** 미어캣을 잡는 보통 잡기(체크 아님)는 `small` 등급이고 `CAMERA_LEAN.small = 0`(`src/fx/impactTier.js:12`)이다. 원래부터 카메라가 다가가지 않는다.
- **agy:** 「→미어캣」을 1.2~1.3초로 줄이자 → 버렸다. 그렇게 줄이려면 타격 뒤 0.48초 반응 구간을 잘라야 한다. 계획서 8절 2항이 「반응은 타격 뒤 0.48초 안」으로 정한 것과 부딪친다. 1.82~2.28초가 길다는 근거도 셋이 갈렸다.
- **codex 첫 실행:** 셸을 금지하자 `diary.md`·`stats.json` 을 열지 못했다. 빈 답을 냈고 지어내지는 않았다. 두 파일을 지시서에 붙여 다시 돌렸다.
- **보류(재 보지 않았다):** grok 의 「비숍→룩은 카메라만 도는 컷이 길다」, agy 의 「룩→퀸은 역전 글자·별빛이 오래 머문다」.

## 조정 — 미어캣 반응 세 가지 (시간 그대로)

채택한 것은 codex 안이다. 「반복될 때 잡힌 미어캣의 넘어지는 방향·자세를 바꾸기」. 시간을 늘리지 않고, 넷이 같이 짚은 지겨움에 바로 닿는다.

- `src/fx/captureReaction.js`:
  - 미어캣 반응을 셋으로 나눴다.
  - 그 판에서 앞서 잡힌 미어캣 수에 따라 0·1·2 를 돌아가며 쓴다.
  - 셋 다 「팽이처럼 돌며 튕겨 나가는」 미어캣이고 길이는 1.25초 그대로다.
- `reactionPose(type, t, variant)`: variant 는 미어캣만 쓴다.

| 변형 | 도는 방향 | 최대 높이 | 밀린 거리 | 그 밖 |
| :-- | :-- | --: | --: | :-- |
| 0(첫째) | 3바퀴 | 1.1칸 | 1.0칸 | 지금과 같음 |
| 1(둘째) | 반대로 3바퀴 | 0.8칸 | 1.1칸 | 옆으로 비틀 |
| 2(셋째) | 2바퀴 | 1.15칸 | 0.8칸 | 뒤로 크게 젖힘 |

- 테스트(`test/captureReaction.test.mjs`): 셋이 서로 다르다, 시작 0, 끝은 보관대, 프레임 사이 튐 없음, 넷째는 첫째와 같다, 다른 동물은 무시한다.
- 엔진의 `retireAnimalPiece` 가 `referee.history()` 에서 앞서 잡힌 미어캣을 센다. `debugFading()` 에 `variant` 를 넣었다.
- **브라우저 확인**(`verify-variants.mjs`, 헤드리스 Chrome · dev 서버): 한 판에서 exd5·Qxd5·Qxg2 로 미어캣 셋을 잡았다.
  - 변형: 0·1·2
  - 최대 높이: 1.1·0.8·1.15칸
  - 0.55초 때 밀린 거리: 0.82·1.1·0.8칸
  - 설계값과 맞는다. 그림은 `variants/strip.jpg`.
  - 기본 카메라 거리에서 사람 눈에 다르게 보이는지는 재 보지 않았다.
- 빠른 테스트 220개 통과, `tsc` 오류 0.

## 그대로 둔 것

- 잡기 길이는 바꾸지 않았다.
- 룩→룩(평균 2.67초)은 셋이 「느림」으로 꼽았다. 그러나 21판에서 21번(4.9%)이고, 거울 연출이 그 이유다. 사람 시험 B 에서 다시 본다.

## 재 보지 않았다

- 사람이 이 판정과 같게 느끼는지. 사람 시험 A·B 는 여전히 필요하다.
- 실제 영상(움직임) 대신 12컷 그림이라 생기는 차이.
- 글자를 같은 조건으로 둔 「전·후」 비교. 「전」을 글자 없이 다시 찍으려면 옛 코드로 녹화해야 한다.
- 사람이 두는 판의 조합 비율. 봇끼리 둔 비율은 사람과 다를 수 있다(계획서 8절 1항).
