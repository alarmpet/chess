## 0. 한 줄 답

지금 섬 장면(`src/village/islandScene.ts`)의 **8×8 칸·경제·저장·주민·세 줄 고리는 그대로 두고**, 그 둘레와 위아래만 바꾼다: 바다 위 디오라마 → **깊은 바다 바닥의 유리 돔**. 돔은 코드로 그린 싸구려 유리(프레넬 + 코스틱, 굴절 없음)로 시작하고, 빛줄기·부유 입자·거품·물고기는 전부 인스턴스 한 번씩이다. 체스판에서 「♟ 마을」을 누르면 카메라가 판 아래 물속으로 잠수해 돔 위로 떨어진다. 성능은 **섬 장면 드로우콜을 처음으로 재서**(빈 섬 51 · 건물 8채 134 · 완성 섬 261, §4) 상한 150 을 새 게이트로 건다.

## 3. 아틀란티스 돔 장면 설계

### 3.1 한 장면의 층

위에서 아래로:

1. **체스판 섬의 밑면** — 화면 맨 위, 어둡고 큰 실루엣(둥근 흙판 하나, 1콜). 그 가장자리로 햇빛이 새어 들어와 **빛줄기 4~6가닥**이 돔 꼭대기를 지나 중앙 광장까지 내려온다.
2. **승강 거품관** — 판 밑면 중앙과 돔 꼭대기를 잇는 투명 관. 거품이 위로 흐른다(Points 1콜).
3. **돔** — 반구, 8×8 섬(한 변 8)을 넉넉히 덮는 반지름 6.2. 유리 + 금속 리브 12개 + 기초 링.
4. **돔 안** — 지금 섬 그대로(칸·건물·주민·소품) + 네 구역 바닥 무늬 + 중앙 광장 빛기둥 착지점.
5. **돔 밖 해저** — 모래 바닥 원판(반지름 24, 코스틱), 폐허 기둥·아치 인스턴스, 해초 인스턴스, 산호(기존 GLB) 몇 개, 물고기 떼(기존 인스턴스), 해파리.
6. **물** — 세로 그라디언트 구(배경, 1콜) + `FogExp2`, 부유 입자 Points.

### 3.4 돔 안 네 구역

8×8 을 넷으로 나눈다. 칸 좌표는 그대로라 길·나무·깃발·영향권·이어 하기 저장이 전부 유효하다.

### 3.5 체스판에서 내려가는 전환

지금 구조: 체스 장면과 섬 장면은 **렌더러·캔버스가 따로**이고, 섬이 열리면 체스 렌더를 멈춘다(`setRenderPaused`). 렌더러 하나로 합치는 것은 6,300줄 엔진 손질이라 하지 않는다.

채택: **잠수 크로스페이드 0.9초** (`App.tsx` + `islandScene.ts` 카메라 시작 자세)

| 시각 | 체스 캔버스 | 덮개(DOM) | 마을 캔버스 |
| :-- | :-- | :-- | :-- |
| 0 | 「♟ 마을」 누름. `setCameraPose` 로 카메라가 판 가장자리 아래로 0.4초 내려감(체스 바다에는 이미 수면과 해저가 있다 — `openSea.js` `seaDepth`) | 남색 비네트 0 → 0.7, 거품 8개 CSS 애니메이션 | 아직 없음 |
| 0.4 | 마지막 프레임을 `toDataURL` 로 떠서 `<img>` 로 깔고 렌더 정지 | 비네트 유지 | `createIsland` — 카메라를 **돔 위 높은 곳**(pitch 1.3, 거리 1.6배)에서 시작 |
| 0.4–0.9 | `<img>` 페이드 아웃 | 비네트 0.7 → 0 | 카메라가 지금 자세(pitch 0.74, zoom 1)로 내려옴, 캔버스 페이드 인 |

- `toDataURL` 은 체스 렌더러가 `preserveDrawingBuffer: isAutomatedTest` 라 **렌더 직후 같은 틱에 읽어야 한다**(렌더 루프 안에 「다음 프레임을 찍어라」 플래그). 안 되면 체스 캔버스를 0.5초 더 돌리고 겹친다(그동안 두 장면 합 98+150).
- 돌아올 때(「♟ 체스로」)는 역순 0.6초. 건너뛰기: 두 번째 탭부터는 0.5초로 줄이고, 설정에 「전환 끄기」.
- 측정: 전환 중 콜백 JS ms 를 `perf_probe.mjs` 로 1회(상한 5ms 는 지금 기준 그대로).

## 4. 성능 예산

### 4.1 지금 섬 장면의 드로우콜 — 처음 잰 값 (2026-11-05)

게이트(`tools/drawcall_gate.mjs`)는 **체스 장면만** 잰다(`window.wizardChess.debugRenderCalls`). 섬 장면에는 갈고리가 없어 WebGL `drawElements*`/`drawArrays*` 를 페이지에서 감싸 프레임당 호출 수를 셌다(개발 서버 `localhost:3000`, 커밋 `18caffd`, 창 1024×768, dpr 1, 기본 카메라, 낮). 저장은 백업 뒤 바꿨고 시험 뒤 되돌렸다. 캡처: [빈 섬](../qa/2026-11-05-village-drawcalls-empty.jpg) · [완성 섬](../qa/2026-11-05-village-drawcalls-full.jpg). 기록: [qa](../qa/2026-11-05-village-drawcalls.md).

| 저장 상태 | 콜/프레임 | 삼각형/프레임 |

### 4.2 어디서 늘고 어디서 줄이나 (추정)

## 7. 틀릴 수 있는 곳 · 사용자 결정

### 틀릴 수 있는 곳

1. **영상과 다른 점을 사용자가 원하지 않을 수 있다.** 영상은 돔 없는 열린 동굴 도시이고, 우리는 돔 + 8×8 격자다. 격자를 둥글게 못 바꾸는 이유는 사건 문법(길·나무·깃발·영향권)이 칸 좌표이기 때문이다. 「어항」처럼 보일 위험 — B 가 끝난 캡처로 판단.
2. **드로우콜 추정이 어긋날 수 있다.** §4.2 는 코드를 읽고 센 값이라 ±30 은 틀릴 수 있다. 그래서 AT-0 을 먼저 하고 AT-1 뒤에 다시 잰다.
3. **삼각형 1.2~1.5M/프레임**은 재지 않은 병목이다. Intel UHD 에서 GPU 시간을 이 PC 로는 못 잰다(rAF 환경값). 산호 GLB 를 돔 밖에 몇 개만 두는 것으로 줄이지만, 다른 PC 측정(MG-ENG 남은 것)이 없으면 모른다.
4. **체스 장면 207 vs 게이트 98**(§4.1). 게이트 조건 밖에서 두 배라면 실제 플레이 중 콜 수가 게이트와 다르다는 뜻이다. 이 계획과 별개로 원인 확인이 필요하다.
5. **`toDataURL` 전환**은 `preserveDrawingBuffer` 가 꺼진 체스 렌더러에서 타이밍을 맞춰야 한다. 안 되면 두 캔버스를 0.5초 겹친다.
6. **코스틱 셰이더 출처**: `openSea.js` 의 `caustic()` 이 「after Dave Hoskins」인데 `CREDITS.md` 가 없다. Shadertoy 기본 라이선스는 CC BY-NC-SA 라 **원문 확인 전에는 돔에 재사용하지 않고** 자체 노이즈 무늬로 대체한다. 확인 뒤 결정.
7. 어린이 질문 「물속인데 숨은?」 — 돔 안은 공기라는 설명 한 줄로 충분한지 사람 시험(AT-9)에서 본다.
8. 밤 팔레트가 어두워 카드(잉크 외곽선) 가독성이 떨어질 수 있다. 밤 바닥 최소 밝기를 지금 밤(`PALETTES.night`)과 같게 두고 캡처로 비교한다.
9. 영상 화질이 360p 라 재질·입자의 세부는 못 봤다. 「추정」 표시가 그 한계다.
