# 잡기 30가지 연출 계획서 — 누가 누구를 잡는지 보이게

> 열린 항목은 [STATUS.md](../STATUS.md) 에서 관리한다. 이 문서는 결정의 기록이다. 약어 **CX**.

작성일 2026-11-08. 사용자 요청: 「쫄이 쫄을, 쫄이 비숍을, 비숍이 비숍을 잡을 때… 각각의 상황을 gif 나 영상으로 연출해서 타격감이나 재미를 업그레이드」.
수치는 시작값이다. 재미는 만들어서 보고 만져 봐야 안다.

## 1. 경우의 수

- 잡는 말 6종 × 잡히는 말 5종 = **30가지**. 킹은 잡히지 않는다(메이트에서 판이 끝난다).
- 배역: 폰 미어캣 · 나이트 캥거루 · 비숍 판다 · 룩 코뿔소 · 퀸 호랑이 · 킹 사자(`public/packs/legend/pack.json`).

## 2. 지금 상태 (코드 확인)

잡기 한 번은 이 순서로 간다(`src/wizardChessEngine.js` 3670~3960행).
다가감 → 공격 클립(`Attack`) → 접촉 때 잡힌 말 `Hit` → 타격 때 `landImpact` → 공격자가 칸으로 들어감 → 카메라 복귀.

화면에서 갈리는 것은 두 갈래뿐이다.

| 갈래 | 정하는 것 | 가짓수 | 코드 |
| :-- | :-- | :-- | :-- |
| 잡는 말 | 필살기 모양·글자(뽁!·퍽!·쿵!·쾅!·샤악!·어흥!)·소리 | 6 | `src/fx/signatureFx.js:9` |
| 잡히는 말 | 충격 세기 3단계(작음·중간·큼). 체크면 한 단계, 메이트면 가장 크게 | 3 | `src/fx/impactTier.js:15` |

- 그래서 지금 구별되는 장면은 **6 × 3 = 18가지**다. 「판다가 판다를」과 「판다가 코뿔소를」은 똑같이 보인다.
- **잡힌 말의 반응은 5종 모두 같다**: `Hit` 클립 → 무릎 꿇고 어지러운 별 → 보관대. 동물 무게나 성격이 드러나지 않는다.
- **체급 차이가 연출에 없다.** 폰(미어캣)이 퀸(호랑이)을 잡아도 퀸이 폰을 잡을 때와 같은 「큼」이다. 잡히는 말만 보기 때문이다.
- **시간 예산이 이미 빠듯하다.** 잡기 한 수 대기 5~6초가 숙련자에게 길다는 항목(STATUS TA-8)이 열려 있다. 빠른 대국(`fxSettings().quick`)은 카메라 이동을 뺀다.

## 3. 측정 — 어떤 조합이 실제로 자주 나오나

봇끼리 60판(쉬움·보통 번갈아, 고정 시드)을 둔 결과다. 스크립트는 [pair_sim.mjs](../research/2026-11-08-capture-pairs/pair_sim.mjs), 원자료는 [pair_sim-60.json](../research/2026-11-08-capture-pairs/pair_sim-60.json).

- 60판, 5,251수, 잡기 1,121번(한 판에 18.7번). 그중 체크가 걸린 잡기 109번, 메이트 잡기 16번.
- **30칸이 모두 한 번 이상 나왔다.** 칸마다 가장 짧은 수순도 원자료 `shortest` 에 있다(CX-0 녹화 국면으로 쓴다).

| 묶음 | 칸 | 비율 |
| :-- | :-- | :-- |
| **폰이 잡힘** | 폰→폰 12.3 · 퀸→폰 9.6 · 룩→폰 8.1 · 나이트→폰 6.7 · 비숍→폰 6.7 · 킹→폰 1.4 | **44.8%** |
| 맞교환(같은 종끼리) | 룩→룩 5.1 · 나이트→나이트 4.6 · 비숍→비숍 3.4 · 퀸→퀸 3.2 | 16.3% |
| 작은 말끼리 | 비숍→나이트 5.3 · 폰→나이트 5.1 · 폰→비숍 5.1 · 나이트→비숍 2.6 | 18.1% |
| 큰 말이 작은 말을 | 퀸→나이트 2.7 · 퀸→비숍 2.6 · 룩→비숍 2.1 · 룩→나이트 1.2 · 퀸→룩 1.0 | 9.6% |
| **역전(작은 말이 큰 말을)** | 비숍→룩 1.9 · 나이트→룩 1.7 · 룩→퀸 1.5 · 비숍→퀸 1.2 · 폰→퀸 1.0 · 나이트→퀸 0.7 · 폰→룩 0.5 | **8.5%** |
| 킹이 잡음(폰 제외) | 킹→비숍 1.7 · 킹→룩 0.5 · 킹→나이트 0.4 · 킹→퀸 0.2 | 2.8% |

읽은 것:
- 잡기의 절반 가까이가 **폰이 잡히는 장면**이다. 층 2의 미어캣 반응은 가장 자주 보이니 가장 짧고 가벼워야 한다.
- **같은 종끼리 맞교환은 16%로 흔하다.** 거울 대결을 크게 만들면 금방 지겹다. 작게 둔다(5절 층 3 수정).
- 점수 차 3점 이상 역전(폰→룩·퀸, 나이트·비숍·룩→퀸)은 **4.9%**로 드물다. 한 판에 0.9번꼴이다. 큰 연출을 쓰기 좋은 칸이다. (처음 판에 3.4% 로 적은 것은 룩→퀸을 빼고 센 값이었다. 11-08 CX-1 때 고침)

봇의 수 고르기는 사람과 다르다. 비율은 「무엇부터 손볼지」 순서를 정하는 데만 쓴다. 사람 대국의 비율은 재 보지 않았다.

## 4. 원칙

1. **수와 판정은 바꾸지 않는다.** 연출은 체스가 끝난 뒤의 표현이다.
2. **잡기 한 수의 총 시간을 늘리지 않는다.** 새 연출은 지금 있는 구간(공격 클립 · 타격 뒤 0.48초 · 카메라 복귀) 안에 넣는다. 특별 조합만 0.3초까지 더 쓴다. 빠른 대국에서는 특별 연출도 짧은 판으로 바뀐다.
3. **자주 나오는 것은 작게, 드문 것은 크게.** 흔한 폰끼리 잡기에 큰 연출을 쓰면 세 판째에 지겹다.
4. **만화처럼.** 피·무기 없음. 잡힌 말은 다음 판에 멀쩡히 돌아온다.
5. **30칸을 다 따로 만들지 않는다.** 「공격 6 × 반응 5」를 조립해 30가지가 저절로 갈리게 하고, 이야기가 있는 몇 칸만 특례를 둔다.

## 5. 설계 — 세 층을 조립한다

### 층 1. 잡는 말의 공격 (6, 있음 → 더 갈리게)

| 동물 | 지금 | 바꿀 방향 |
| :-- | :-- | :-- |
| 미어캣(폰) | 뽁! | 까치발로 섰다가 박치기. 작고 빠르게 |
| 캥거루(나이트) | 퍽! | 꼬리로 버티고 두 발 차기. 차인 쪽이 포물선으로 날아감 |
| 판다(비숍) | 쿵! | 대각선으로 데굴 굴러 들이받기 |
| 코뿔소(룩) | 쾅! | 땅을 긁고 직선 돌진. 지나간 칸에 먼지 줄 |
| 호랑이(퀸) | 샤악! | 할퀴기 빛줄기 세 줄 |
| 사자(킹) | 어흥! | 포효 충격파 고리. 잡힌 말이 바람에 밀려남 |

새 클립 없이 할 수 있는 것(자세 기울기·이동 궤적·입자 모양)부터 하고, 클립이 필요한 것(두 발 차기 등)은 `chess-character-pipeline` 의 클립 추가 단계로 보낸다.

### 층 2. 잡히는 말의 반응 (5, 새로)

지금은 5종이 같은 반응이다. 동물 무게와 성격으로 가른다.

| 잡히는 동물 | 반응 | 무게감 |
| :-- | :-- | :-- |
| 미어캣(폰) | 팽이처럼 돌며 높이 튕겨 나감 | 가벼움 — 멀리 날아감 |
| 캥거루(나이트) | 한 번 통 튀어 버티려다 엉덩방아 | 탄력 |
| 판다(비숍) | 뒤로 데굴데굴 굴러 감 | 둥글둥글 |
| 코뿔소(룩) | 한 박자 버티다 쿵 옆으로 넘어짐, 판이 살짝 출렁 | 무거움 — 거의 안 날아감 |
| 호랑이(퀸) | 공중제비 돌고 별이 가장 많음 | 큰 말이 당했다는 느낌 |

조립 결과: 공격 6 × 반응 5 = 30가지가 서로 다르게 보인다.

### 층 3. 맞대결 특례 (이야기가 있는 칸만)

| 특례 | 해당 칸 | 연출 | 시간 |
| :-- | :-- | :-- | :-- |
| **역전(체급 차이)** | 잡는 말이 잡히는 말보다 3점 이상 낮을 때(5칸: 폰→룩·퀸, 나이트·비숍·룩→퀸). **CX-1 에서 구현(11-08)** | 「역전!」 글자, 슬로 한 박자, 작은 쪽이 의기양양 포즈. 세기는 잡히는 말이 아니라 **점수 차**로 올린다 | +0.3초까지 |
| **거울 대결** | 같은 동물끼리(폰↔폰 제외 4칸: 나이트·비숍·룩·퀸). 합쳐 16%로 흔하다 | 잡히는 쪽이 같은 동작을 반쯤 따라 하다 튕겨 남. 짧게 | 늘리지 않음 |
| **사자의 포효** | 킹이 잡을 때(5칸) | 충격파가 주변 말까지 살짝 흔듦 | 늘리지 않음 |
| **흔한 폰끼리** | 폰 → 폰 | 가장 짧고 가볍게. 대신 그 판 몇 번째 폰 잡기인지에 따라 소리 높이만 오른다(연속 콤보 느낌) | 줄일 수 있으면 줄임 |

세기 규칙(지금 `impactTier`)을 「잡히는 말 + 점수 차 + 체크·메이트」로 바꾸는 것이 층 3의 핵심이다. 순수 함수라 테스트로 30칸 전부 고정할 수 있다.

## 6. GIF·영상은 어디에 쓰나

세 군데에 쓴다.

1. **기준 영상(지금 모습).** 30칸 각각을 같은 카메라·같은 국면 조건으로 찍어 GIF 로 남긴다. 고치기 전과 뒤를 나란히 놓고 비교하는 기준이다.
2. **콘셉트 영상(선택).** 역전·거울 대결 같은 특례 몇 개는 Google Flow 로 만화 콘셉트 영상을 먼저 뽑아 동작을 정한다. 크레딧이 드니 사용자가 정한다(9절). 콘셉트는 참고만 하고 게임 에셋으로 쓰지 않는다.
3. **결과 갤러리.** `docs/qa/` 에 30칸 GIF 를 6×5 표로 놓은 페이지를 만든다. 사람 시험(7절)도 이 GIF 로 한다.

**찍는 방법 (CX-0 에서 만든다).**
- 국면: 시뮬이 찾은 「그 조합이 나오는 가장 짧은 수순」을 이어 하기 저장(`wildcrown.resume.v1`)으로 넣고 마지막 잡기 한 수만 둔다. 시뮬에 안 나온 칸은 손으로 수순을 짠다.
- 녹화: 게임 화면은 WebGL 캔버스 하나다(`WebGLRenderer`, 60행). 페이지 안에서 `canvas.captureStream()` + `MediaRecorder` 로 실제 속도 webm 을 찍고, ffmpeg-skill 로 GIF·나란히 비교 영상을 만든다. 이 방법이 이 엔진에서 되는지는 **재 보지 않았다.** 안 되면 지난번처럼 시계를 0.15배로 늦추고 연속 캡처한다([PT 캡처 기록](../qa/2026-11-07-pt-capture.md)).
- 화면 글자(체크메이트 띠 같은 HTML)는 캔버스 녹화에 안 들어간다. 잡기 연출은 3D 안 글자라 들어간다.
- 녹화 뒤 저장은 시험 전으로 되돌린다.

**사람 시험 A(구분).** 처음 보는 사람 3명에게 소리 끈 GIF 30개를 섞어 보여 주고 「잡은 동물·잡힌 동물」을 맞히게 한다. 지금 모습과 고친 뒤를 같은 방법으로 잰다. 잡힌 쪽은 지금 모두 같은 반응이라 동물 모양으로만 맞혀야 한다. 고친 뒤 정답률이 오르는지 본다.

## 8. 틀릴 수 있는 곳

1. **봇의 비율은 사람과 다르다.** 우선순위가 바뀔 수 있다. 사람 대국 기록이 쌓이면(세션 로그) 다시 센다.
2. **반응을 다르게 하면 퇴장 시간이 갈린다.** 코뿔소가 버티다 넘어지는 동안 다음 수를 못 두면 TA-8 이 나빠진다. 반응은 타격 뒤 0.48초 안에 끝나게 자른다.
3. **역전 연출은 지는 쪽 기분을 상하게 할 수 있다.** 퀸을 폰에게 잃은 사람에게 「역전!」이 놀림처럼 보일 수 있다. 잡은 쪽이 사람일 때만 크게, 봇이 잡았을 때는 작게 하는 안을 시험한다.
4. **카메라 거리에서 안 보일 수 있다.** 지난번 예비 동작(14% 눌림)은 기본 카메라에서 안 보였다. 반응은 크게(위치·회전) 움직여야 한다.
5. **captureStream 녹화가 rAF 29Hz 제약을 받는다**(ego-browser, 메모리 기록). GIF 는 충분하지만 부드러움 비교용으로는 모자랄 수 있다.

## 9. 사용자가 정할 것

1. 콘셉트 영상을 Flow 로 뽑을지(크레딧 사용) — 아니면 기준 GIF 만 보고 바로 코드로 간다.
2. 역전 연출을 봇이 잡았을 때도 크게 할지.
3. 첫 PR 범위: CX-0·CX-1(권장) 또는 CX-0 만.
