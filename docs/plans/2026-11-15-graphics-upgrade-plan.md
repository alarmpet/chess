# WILD CROWN — 그래픽 업그레이드 계획 (타격·특수 효과 · 플레이 화면 · UI)

작성일: 2026-11-15. 사용자 요청: `smartdaddy-carbon-vs-fable.pages.dev` 의 게임들을 플레이해 보고, 우리 게임의 UI/UX · 플레이 화면 · 타격 효과 · 특수 효과를 올리는 방향의 계획서를 쓴다.

앞선 문서: [사례 조사](../research/2026-11-14-fable-gamedev/findings.md) · [플레이 화면 개편 기록](../qa/2026-11-13-play-screen.md) · [카드·룩 기록](../qa/2026-11-14-card-grades.md) · [손맛 계획](2026-11-12-intuitive-replay-plan.md).

## 1. 무엇을 봤나

그 사이트는 같은 과제 다섯 개를 Gemini Carbon 과 Claude Fable 5.2 에게 맡긴 결과물 10개를 올려 둔 곳이다. **페이블판 게임 셋을 브라우저(ego-browser)로 직접 눌러 플레이했다.**

| 게임 | 한 것 | 못 한 것 |
| :-- | :-- | :-- |
| 뇌운비격(2D 횡스크롤 슈팅) | 도입 그림 넘기기 → 1막에서 이동·쏘기·모아 쏘기·필살기·고유기 | 보스까지 가지 않았다 |
| 빌리꾸마! 배추골 순자 할매(3D 오픈월드) | 촬영 모드 「효자손 한 방」에서 걷기·효자손 연타·고함 | 차량·대포·다른 장 |
| 잔향의 계승자(3D 헌터 MMORPG) | 헌터 등록 → 마을, 「보스 레이드로 바로」에서 평타·기술 Q/E/R·구르기 | 필드 사냥, 보스 2단계 |

- **카본판 다섯 개, 펠리컨 영상, 용 영상은 보지 않았다.** 이 계획은 페이블판 셋에서 본 것만 근거로 한다.
- 소스는 **읽기만** 했다(슈팅 `game.js`·`render.js`, 할매 `effects.js`·`camera.js`·`main.js`). 라이선스 표시가 없어 **코드·그림은 한 줄도 가져오지 않는다.** 구조만 배운다.
- 캡처는 저장소에 넣지 않았다(남의 그림이다). 이 PC 의 `D:\tmp\cvf\` 에만 있다.
- 소리는 듣지 못했다(자동 조작이라 화면만 봤다). 소스에서 효과마다 소리를 같이 부르는 것만 확인했다.

## 2. 본 것 — 세 게임이 공통으로 하는 일

### 2-1. 타격 한 번에 여러 겹이 동시에 나온다

슈팅 게임에서 피격 한 번에 `hitstop(16); shake(20); flash(0.55, '#ff2030'); slow = 45; 소리 둘` 이 한 줄로 나간다. 할매 게임도 같은 꾸러미다(`burst` · `spray` · `shake` · `flash` · `ring` · `explode`, 그리고 `hitstop` 과 느린 화면 0.35배).

| 겹 | 화면에서 본 것 |
| :-- | :-- |
| 멈춤(히트스톱) | 맞는 순간 몇 프레임 정지 |
| 흔들림 | 세기가 사건마다 다르다(5 ~ 20), 큰 것만 크게 |
| 번쩍임 | **색이 있다** — 내가 맞으면 빨강, 방패로 막으면 주황, 번개면 하늘색 |
| 고리 | 맞은 자리에서 퍼지는 고리, 색·굵기·속도가 다르다 |
| 파편·먼지 | 할매: 맞은 자리에 흰 조각이 튀고 먼지 구름이 **몇 초 남는다** |
| 날아가는 몸 | 할매: 맞은 사람이 건물 벽까지 날아가 붙는다 |
| 숫자·낱말 | 슈팅 `+100` `+200`, MMORPG 회복 `+94` 가 그 자리에서 뜬다 |
| 보상이 흩어짐 | 슈팅: 적이 터지면 동전이 흩어지고 내가 지나가며 줍는다 |
| 말풍선 | 할매: 맞은 사람 머리 위에 「으아아악!」「아이고오~!」 |

### 2-2. 빛은 더하기로 겹친다

슈팅 `render.js` 에 `lighter`(더하기 합성)가 47번 나온다. 모아 쏘기 광선은 흰 심 + 하늘색 겉 + 꼬인 나선 두 줄 + 가지 번개가 겹쳐 있다. MMORPG 의 회복 기술은 캐릭터를 감는 나선 띠 두 겹이다. **효과 하나가 한 덩어리가 아니라 서너 겹**이다.

### 2-3. 위험은 미리 바닥에 그린다

MMORPG 보스전: 공격이 떨어질 자리에 주황 원이 먼저 깔리고, 그 위에 기술 이름 딱지(「물기둥」)가 붙는다. 오른쪽에는 「읽어 낸 패턴」 목록이 있어 본 공격은 대처법이 적히고 못 본 것은 `?` 다.

### 2-4. UI 는 틀과 그림이 있다

| 요소 | 본 것 |
| :-- | :-- |
| 초상화 | 슈팅: 왼쪽 위 육각 틀의 주인공 얼굴, 대사 상자에도 얼굴. MMORPG: 둥근 틀 + 레벨 배지 |
| 기울인 판 | 슈팅 HUD 는 직사각형이 아니라 평행사변형, 무기 칸은 마름모 |
| 구슬 | MMORPG: 체력·마나가 숫자 든 붉고 푸른 구슬 |
| 기술 칸 | 그린 아이콘 + 단축키 글자 + 재사용 대기 숫자가 아이콘 위에 크게 |
| 보스 줄 | 이름 + 단계 + 체력 아래 얇은 두 번째 줄 |
| 알림 | 할매: 왼쪽 위에 「수입 +2,000」「연쇄 난장판 ×4」가 쌓였다 사라진다. 돈 숫자 밑에 `+₩2,000` |
| 상황 조작법 | 슈팅: 처음 몇 초만 화면 가운데에 「Z 쏘기 · C 모아 쏘기 …」 |
| 도입 | 슈팅·MMORPG: 그림 한 장 + 붓글씨 한두 줄, 위에 진행 점, 「건너뛰기」 |

### 2-5. 카메라가 사건에 반응한다

할매 `camera.js`: 달리면 시야각 62 → 66, 탈것이면 속도에 따라 더, 사건 때는 정해 둔 자리로 넘어가는 연출 카메라(`setCine`), 흔들림은 카메라 위치에 더한다.

## 3. 우리는 지금 어디인가

있는 것(저장소에서 확인):

- 잡기 크기 세 단계(`src/fx/impactTier.js`): 멈춤 0.05 ~ 0.11초 · 입자 18 ~ 70개 · 고리 · 흔들림 · 느린 화면(큰 것만) · 낱말(「뾱!」「콩!」「쾅!」) · 카메라 기울임.
- 말 종류별 서명 효과(`signatureFx.js`), 같은 말끼리 잡기·사자 포효·폰 연쇄 음높이(`captureSpecial.js`), 왕관 보석, 딱지, 금빛 결정타.
- 플레이 화면: 인스턴스 표식(갈 칸·잡기·위험), 크림색 단추, 비네트. 카드 등급 효과(CSS).

없는 것(엔진에서 낱말을 세어 확인 — `trail` 0, 떠오르는 숫자 0, 후처리 0):

| 빈 곳 | 지금 | 사이트에서 본 것 |
| :-- | :-- | :-- |
| 색 있는 번쩍임 | 맞은 말은 하얗게 번쩍인다(0.16초, `impactFx.flash` — **처음 쓴 판에는 「없다」고 적었는데 틀렸다, 착수하며 코드에서 확인**). 화면 번쩍임은 없었다 | 사건마다 색이 다른 번쩍임 |
| 겹 | 고리 하나 + 입자 한 종류 | 심·겉·나선·불똥 서너 겹, 더하기 합성 |
| 잔상·궤적 | 없다 | 돌진·광선에 꼬리 |
| 남는 것 | 잡힌 뒤 자리에 아무것도 안 남는다 | 먼지·연기가 몇 초 남는다 |
| 보상의 이동 | 도토리·카드가 **판에서 HUD 로 날아오지 않는다**(보석만 날아온다) | 동전이 흩어지고 모인다, 숫자가 뜬다 |
| 맞은 쪽의 반응 | 표정·말풍선 없다 | 머리 위 한마디 |
| HUD 의 얼굴 | 차례 판은 글자뿐, 상대가 누구인지 화면에 얼굴이 없다 | 초상화 틀 |
| 판 시작·끝 | 바로 시작한다 | 그림 한 장 + 한 줄 |
| 카메라 | 큰 잡기에 기울임만 | 시야각 변화, 연출 자리 |

## 4. 원칙 — 이 게임에 맞게 고른다

1. **체스는 읽혀야 한다.** 슈팅 게임의 화면 가득한 폭발은 가져오지 않는다. 효과는 **한 칸 반 안에서 0.6초 안에** 끝나고, 끝나면 판이 그대로 보여야 한다.
2. **크기는 순간을 따른다.** 지금의 세 단계를 지킨다. 새 겹은 주로 `medium`·`big` 에 얹고 `small` 은 가볍게 둔다(폰 잡기는 한 판에 여러 번 나온다).
3. **한 사건 = 한 꾸러미.** 사이트의 두 게임처럼 효과를 부르는 곳을 한 군데로 모은다 — 「이 사건의 멈춤·흔들림·번쩍임·고리·소리」가 표 한 줄이 되게.
4. **예산이 좁다.** 첫 화면 JS 는 gzip 395/400KB, 이 장면은 GPU 병목(11-11 기록 21.6ms), 드로우콜 상한 100(지금 68 ~ 75). 그래서:
   - 새 효과 코드는 **늦게 받는 묶음**에 넣는다(첫 화면 +0KB 가 목표).
   - 전체 화면 후처리(블룸 등)는 넣지 않는다. 빛은 **더하기 합성 스프라이트**로 낸다.
   - 효과는 인스턴스 메시·`Points` 하나에 모은다. 사건 하나에 드로우콜 +3 이하.
5. **「효과 줄이기」를 지킨다.** 흔들림·번쩍임·느린 화면은 그 설정에서 꺼진다(지금 규칙 그대로).
6. **귀여운 동물이다.** 피·파괴가 아니라 별·깃털·먼지·도토리. 맞은 말은 다치지 않고 「아야!」 하고 물러난다.
7. **남의 그림·코드는 쓰지 않는다.** 구조만 배운다. 새 그림은 이 PC 의 경로(Flow/ComfyUI)로 만든다.

## 7. 하지 않을 것

- 전체 화면 후처리(블룸·색수차·모션 블러) — GPU 병목이고 묶음이 는다.
- 물리 래그돌 — 할매 게임의 「날아가 벽에 붙기」는 좋지만 물리 엔진이 필요하다. 지금의 리그 동작(물러나기·구르기)으로 흉내만 낸다.
- 화면을 가리는 긴 폭발·긴 도입(슈팅 게임의 그림 세 장짜리 도입). 체스는 판이 먼저다. 도입은 한 장, 1.5초.
- 구슬·기술 칸 같은 RPG 식 HUD. 우리에게는 체력도 기술 대기도 없다.
- 사이트의 코드·그림·글꼴 가져오기.

## 8. 사용자가 정할 것

1. **새 그림을 만들까.** GX-10·GX-11 의 초상·판 끝 그림을 카드 그림에서 잘라 쓰면 지금 바로 되고, 새로 그리면(Flow, 왕국 × 왕 = 최소 2장, 상대 사다리마다 그리면 6장 이상) 더 좋지만 하루 이상 걸린다.
2. **말풍선(GX-8)을 넣을까.** 귀엽지만 판 위에 글이 는다. 등 표식처럼 「없는 편이 낫다」가 될 수 있어, 한 마리로 먼저 보여 드리고 정하는 편이 안전하다.
3. **첫 PR 을 타격 1 로 시작해도 되는가**, 아니면 얼굴 있는 UI 를 먼저 볼 것인가.

## 9. 이 계획의 한계

- 사람 시험 없이 내 눈으로 고른 것이다. 세 게임을 각각 몇 분씩만 했고, 자동 조작이라 손맛(입력 → 반응의 느낌)과 소리는 직접 느끼지 못했다.
- 카본판과 견주지 않았다. 「페이블이 더 잘한 점」이 아니라 「페이블판 셋에서 본 것」이다.
- 숫자 목표(드로우콜 ≤ 80 등)는 지금 값(68 ~ 75)에서 잡은 것이고, 효과를 넣어 보기 전에는 맞는지 모른다.
- 실제 폰에서의 성능은 재 보지 않았다. GX-4·GX-15 는 폰에서 먼저 재야 한다.
