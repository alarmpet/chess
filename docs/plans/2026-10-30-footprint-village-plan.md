# 발자국 마을 계획서 — 내가 둔 체스가 내 마을이 된다

작성일 2026-10-30. 근거 자료는 [라운드 기록](../research/agent-rounds/2026-10-30-footprint-village/README.md)에 있다.
이 문서의 효과 예상은 전부 가설이다. 실제 플레이어로 잰 수치는 아직 없다.

## 1. 결론

체스는 규칙이 고정이라 말을 강하게 키울 수 없다. 그래서 **말의 힘이 아니라 말의 삶을 키운다.**

- 대국에서 내 말이 지나간 칸은 8×8 마을의 길이 된다.
- 말이 잡힌 칸에는 그 말이 심은 나무가 자란다.
- 캐슬링은 성문을, 승급은 그 폰의 집을 세운다.
- 폰 8마리는 같은 폰이 아니다. e2 폰은 매 판 같은 아이고, 많이 뛸수록 자기 혼자 자란다.
- 다른 마을과 같을 수 없다고 장담할 수는 없다. 같은 기보를 두면 같은 흔적이 나온다. 하지만 내 마을은 내 기보의 화석이다.

체스 수와 판정은 절대 바뀌지 않는다. 마을은 체스의 결과를 받기만 하고, 체스에 주는 것은 외형뿐이다.

세 모델 모두 후보 6개 중 이 방향을 1위로 골랐다. 다만 셋 다 "전부 한꺼번에 만들면 무너진다" 고 했고, 줄인 형태가 아래 계획이다.

## 2. 사용자 예시 판정

| 예시 | 판정 | 이유 |
| :--- | :--- | :--- |
| 마을 발전 | 채택 | 재화로 짓지 않는다. 기보가 짓는다 |
| 캐릭터 레벨업 | 채택(외형만) | 이미 있는 4단계 모델을 말 개체별 성장으로 쓴다 |
| 농사 | 핵심에서 제외 | 작물 타이머는 체스 사건이 필요 없어 대국과 끊긴다. 나무·꽃은 흔적 표현으로만 남긴다 |
| 전쟁 | 제외 | 별도 전투력은 "강해진 말" 로 읽혀 표시 원칙과 어린이 기준에 어긋난다 |
| 방어 | 제외 | 습격·손실이 접속 압박이 되고 두 번째 규칙이 생긴다 |
| 방치형 | 재화 방치는 제외 | 재화가 쌓이면 대국을 안 두고 수금만 하게 된다. 시간 처리 구조만 참고한다 |

이번 판정은 사용자 예시를 없애자는 뜻이 아니다. 시제품을 만져 본 뒤 뒤집을 수 있다. 재는 방법은 6절에 있다.

## 3. 플레이어의 하루

**저녁 한 판, 이것이 진짜 콘텐츠다.**

1. 평소처럼 둔다. 라이벌이든 자유 대국이든 같다.
2. 끝나면 바로 마을로 내려간다. 고를 것은 없다. 이번 판이 남긴 변화가 한 장면으로 재생된다.
   예: "e2 폰이 지나간 길이 돌길이 됐고, b1 나이트가 쓰러진 c3 에 묘목이 났다."
3. 수훈을 세운 말 한 마리가 광장에 나와 있다. 쓰다듬을 수 있다.
4. 바로 다음 판으로 갈 수 있다.

**아침 1분, 있어도 없어도 된다.**

1. 어제 판의 말이 자고 있거나 깨어 있다. 마을 조명은 실제 시각을 따른다.
2. 한 마리가 "이 칸에서 나는 어디로 갈 수 있지?" 하고 물어볼 수 있다. 건너뛰어도 아무것도 잃지 않는다.

### 첫 7일 예시

하루 한 판을 둔다고 가정한 예시다. 의무가 아니다.

| 날 | 일어나는 일 |
| :--- | :--- |
| 1 | 첫 판 뒤 황무지 마을에 첫 발자국 길이 난다. 첫 사건을 만든 말에게 이름을 지어 줄 수 있다 |
| 2 | 어제 길이 아직 있다. 내 판이 쌓인다는 것을 처음 알게 된다 |
| 3 | 잡힌 말의 묘목이 나무로 자란다. 패배한 판도 똑같이 마을을 키운다 |
| 4 | 라이벌을 이기면 소품이 그 말과 함께 광장에 나온다 |
| 5 | 많이 뛴 폰 하나가 혼자 "자람" 단계로 커 보인다. 8마리가 처음으로 달라 보인다 |
| 6 | 캐슬링을 했다면 성문이 선다. 안 했다면 평범한 길이 넓어진다 |
| 7 | 첫날 사진과 오늘 사진을 나란히 본다 |

## 4. 핵심 규칙

**개체는 시작 칸이다.** 말 ID 는 `w_e2`, `w_b1` 같은 시작 칸 슬롯 16개다.
대국 끝에 `referee.history()` 의 수 기록(from·to·captured·promotion)을 처음부터 되짚어 칸→슬롯을 추적한다.
엔진은 승급 때 새 객체를 만들기 때문에(`src/wizardChessEngine.js:3173`) 화면 객체에 기대지 않는다. 승급한 폰도 기록상 같은 슬롯이다.
순수 함수라서 테스트로 앙파상·캐슬링·승급을 검증할 수 있다.

**칸은 세 단계까지만 변한다.** 흙 → 길 → 돌길. 그 뒤로 넘치는 발자국은 이웃 칸으로 번진다.
같은 오프닝만 두면 중앙만 겹치고 외곽이 빈다는 지적(agy·grok)에 대한 통합자의 대응이고, 효과는 재 봐야 안다.

**말 외형은 슬롯별로 자란다.** 지금은 역할별로 외형이 같다. `lookFor(color, type)` 를 슬롯 기준으로 넓히면 8마리 폰의 단계가 서로 달라진다.
새 모델 없이 기존 48개 GLB 를 쓴다. 대국 참가 수로 열리고, 첫 문장은 늘 "외형만 바뀌고 수는 같습니다" 이다.

**마을에는 말을 1~3마리만 그린다.** 대국 시작 위치가 드로우콜 140 이다. 16마리를 더 그리면 그리기가 그만큼 늘어난다.
타일과 나무는 뼈대 없는 메시라서 인스턴싱으로 합칠 수 있다.

**이름은 사건이 생긴 말부터 지어 준다.** 첫날 16개를 입력시키지 않는다. 이름 칸은 비어 있어도 된다.

**재화는 없다.** 소품은 지금처럼 체크메이트로만 얻는다. 시작 단계에는 알림도 없다.

## 5. 넣지 않는 것 (중독의 선)

사용자가 말한 "계속 접속하고 싶다" 는 **보고 싶어서** 오는 것이지 **안 오면 손해라서** 오는 것이 아니다.

| 넣지 않는다 | 대신 |
| :--- | :--- |
| 굶음·병·죽음 | 비우면 잔다. 돌아오면 그대로다 |
| 연속 접속 기록, 놓친 보상 숫자 | 없음 |
| 시간제 재화 수금 | 대국이 끝나야 마을이 변한다 |
| 긴 대기 타이머 | 진행의 열쇠는 한 판 |
| "지금 안 오면 손해" 알림 | 첫 단계는 알림 없음. 나중에도 동의한 경우만 |
| 뽑기 | 없음 |
| 강한 말로 오해할 표시 | 모든 성장 화면 첫 문장에 수 동일 문구 |

걱정거리 하나: 말을 살리려고 나쁜 수를 두게 될 수 있다. 그래서 잡힌 말도 나무를 남기고, 수훈마는 승패와 상관없이 뽑는다. 재 볼 실험 2번이 이것을 본다.

## 6. 만들기 전에 먼저 재 볼 것 (이틀)

기준은 혼자 재 볼 수 있는 규모로 잡은 설계값이다. 관측값이 아니다.

1. **마을 잔상.** 실제 기보 3판으로 8×8 그림을 만들어 라이벌 소품 화면과 나란히 놓는다. 사용자 포함 3명에게 내일 다시 보고 싶은 쪽을 묻는다. 둘 다 아니면 계획을 다시 쓴다.
2. **같은 아이.** "e2 폰은 매 판 같은 아이" 일기 3줄을 보여 준다. 누가 어느 폰인지 관심이 없으면 이름·개체를 빼고 마을 지형만 남긴다.
3. **기술 확인.** 실제 기보로 슬롯 추적을 돌리고, 마을 화면 드로우콜을 잰다. 슬롯이 어긋나면 진행하지 않는다.

## 7. 만드는 순서

**1주차: 기록**
- `src/village/roster.js`: 수 기록 → 슬롯별 사건, 칸별 방문·잡힘. 앙파상·캐슬링·승급 테스트.
- 저장: localStorage 에 마을 상태. 판이 끝날 때 한 번 저장.
- 저장 내보내기·가져오기. 브라우저 정리로 애착이 사라지는 사고를 막는다(agy 지적).

**2주차: 마을 화면 (여기서 사용자가 만져 본다)**
- 대국 뒤 8×8 마을 씬. 흙·길·돌길, 묘목·나무.
- 수훈마 1마리, 쓰다듬기, 기존 Idle·Cheer 클립.
- 판 종료 장면에 "이번 판이 남긴 변화" 재생.

**3~4주차: 애착**
- 슬롯별 외형 성장, 이름 짓기, 캐슬링 성문, 승급 집, 소품을 든 말의 광장 등장.
- 실제 시각 낮밤, 자는 말, 돌아왔을 때 어제 마을 한 장.

**그 뒤**
- 말의 체스 질문 놀이, 첫날과 오늘 비교 사진, 라이벌별 구역.

**서버가 생긴 뒤**
- 기기 간 동기화, 친구 마을 방문과 방명록. 대결이 아니라 구경이다.

## 8. 오픈소스에서 가져올 것

코드는 복사하지 않는다. 구조만 참고한다.

| 저장소 | 라이선스 | 배울 점 | 쓰는 곳 |
| :--- | :--- | :--- | :--- |
| Tendsty/gooboo | GPL-3.0 | 시간차 하나로 모든 모듈을 처리, 돌아오면 요약 화면 | 돌아왔을 때 어제 마을 한 장 |
| ihtasham42/progress-knight | Unlicense | 환생해도 이전 삶이 남는다 | 판마다 말은 시작 칸으로 돌아가도 이력은 남는다 |
| IdreesInc/Pocket-Bird | MPL-2.0 | 쓰다듬기, 늘 곁에 있음, 작은 수집 | 광장의 말 |
| Trimps/Trimps.github.io | GPL-2.0 | 오프라인 처리를 사용자가 고른다 | 지금은 쓰지 않음 |
| victorqribeiro/isocity | MIT | 아주 작은 아이소메트릭 타일 배치 | 마을 격자 참고 |

GPL 저장소의 코드를 옮기면 이 게임의 라이선스 문제가 생긴다. 게임 전체를 받아 동물만 바꾸는 방식은 쓰지 않는다. 대국과 끊긴 두 번째 게임이 되고, 하나의 게임을 복제하는 일이 되기 때문이다.

REA 는 `progress-knight` 에 돌렸다. 소스가 공개된 게임이라 코드를 직접 읽는 편이 더 많은 것을 알려 줬다.

## 9. 틀릴 수 있는 곳

1. 재화 없는 발전이 금방 시시해질 수 있다. 마을이 다 차거나 변화가 배경처럼 느껴지면 선택권이 더 필요하다. codex 는 이때 필요한 최소는 재화보다 "남길 장소나 장면을 고르는 선택권" 이라고 봤다.
2. 체스를 잘 모르는 사람은 판을 끝내지 못해 마을이 자라지 않는다. 쉬운 라이벌이 이 입구가 돼야 한다.
3. 체스 유저는 마을을 군더더기로 여길 수 있다. 판 종료 뒤 장면은 건너뛸 수 있어야 한다.
4. 아침 방문이 정말 생길지는 모른다. 세 모델과 통합자 모두 근거가 없다. 첫 목표는 저녁 한 판 뒤의 애착이다.
5. "다시 들어오고 싶다" 를 증명한 자료는 찾지 못했다. 체스와 마을을 이은 성공 사례도 이번 조사에서는 찾지 못했다.

## 10. 사용자가 정할 것

1. 재화 없이 시작하는 데 동의하는가. 농사·전쟁을 포기하기 어렵다면 시제품 뒤에 다시 볼 수 있다.
2. 이틀 실험을 먼저 할지, 바로 1주차로 갈지.
