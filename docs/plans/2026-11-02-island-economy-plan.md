## 0. 사용자 요청과 답

| 요청 | 결정 |
| :--- | :--- |
| 카드를 더 다양하고 풍부하게 | 도감 24칸은 그대로 둔다. 확률 없는 **사건 카드**, 판 사이에 고르는 **직무 배지**, 사건으로 여는 **씨앗**을 더한다 (§3) |

| LLM 협업으로 최선의 방식 | 단계마다 구현 → 세 모델 검토 → 봇 대국과 브라우저 시험 → 사람 판정 (§9) |

## 1. 한 문장 고리

체스를 끝까지 두면 잡은 동물이 카드 주민이 되고, 주민이 밭을 일구고 공장을 돌리고 상점에서 주문을 채우며, 그 결과로 생긴 건물과 다음 주문이 다음 판의 목표가 된다.

## 2. 중도 이탈 — 판 주머니와 이어 하기

### 지금 상태 (저장소에서 확인)

- 카드는 잡는 순간 저장된다. `pay()` 가 `awardCard` 뒤 바로 `saveCollection` 을 부른다 (`src/cards/CardLayer.tsx:76-79`). 판 중간에 `새 게임` 을 눌러도 카드가 남는다.
- `새 게임` 은 판만 비우고 `gamefinished` 를 보내지 않는다 (`src/wizardChessEngine.js:5324` 부근).
- 기권 버튼은 없다. `src/` 전체에서 resign·기권을 찾았지만 나오지 않았다.
- 진행 중인 대국을 저장하는 기능도 없다.
- 카드와 판 끝 사건은 싱글 대국에서만 나온다 (`reportCapture`, `reportGameEnd` 의 `gameMode !== 'single'` 검사).

### 규칙

| 경우 | 카드 | 섬 정산 |
| :--- | :--- | :--- |
| 체크메이트·스테일메이트·무승부로 끝남 | 주머니 전부 확정. 승리면 사자 카드, 빈손이면 위로 카드 | 지금처럼 `settleGame` |
| 기권, 내 수 10수 이상 | 패배로 확정. 주머니 전부와 위로 카드 | 패배 정산 |
| 기권, 내 수 10수 미만 | 주머니 폐기. 확인창에 "이번 판 카드 N장은 들어가지 않아요" | 없음 |
| `새 게임` 을 판 중간에 누름 | 같은 확인창 뒤 주머니 폐기 | 없음 |
| 새로고침, 탭 닫힘, 휴대폰이 탭을 죽임 | 다시 열면 **이어 하기**. 끝내면 확정 | 끝낼 때 |
| 이어 하기를 거절 | 주머니 폐기 | 없음 |
| 멀티플레이 | 카드 없음(지금과 같음). 양쪽 결과를 검증할 수 있을 때 따로 설계 | 없음 |

- **주머니:** 잡는 순간 카드는 지금처럼 날아가지만 "이번 판 주머니"에 들어간다. 판 번호와 함께 localStorage 에 저장해서 이어 하기가 되살린다.
- **보장 횟수:** 첫 카드·희귀 10장·영웅 60장 보장은 확정된 카드로만 센다. 버린 주머니는 보장을 움직이지 않는다.
- **정산 영수증:** 카드와 섬은 저장 키가 다르다 (`wildcrown.cards.v1`, `wildcrown.village.v1`). 판이 끝나면 판 번호가 든 영수증을 먼저 쓰고, 카드와 섬이 각자 처리한 판 번호를 기억한다. 정산 도중 탭이 닫혀도 다시 열면 한 번만 지급된다.
- **이어 하기:** 매 수마다 수 목록을 저장하고, 다시 열면 새 심판에 수를 다시 둔다. 되돌리기에 쓰는 판 스냅샷 코드(`src/wizardChessEngine.js:2495` 부근)와 멀티의 수 적용 코드가 이미 있다. 섬 정산은 `referee.history()` 를 쓰므로 수 목록을 다시 두는 방식이어야 길과 나무가 맞다.
- **10수:** 일찍 퀸을 잡고 기권하는 판을 막는 선이다. 크게 밀리는 초보에게 10수는 길 수 있다. 사람 시험에서 줄이거나 기물 차이로 바꾼다.

이어 하기를 기권보다 먼저 만든다. 이어 하기 없이 주머니만 넣으면 실수로 닫은 어린이가 카드를 잃는다.

## 3. 카드 다양화

도감 24칸, 드롭표, 합성, 보장은 바꾸지 않는다 (`src/cards/economy.js:5-30`). 새 동물이나 5번째 등급은 넣지 않는다. 대신 확률을 늘리지 않는 축 셋을 더한다.

### 3-1. 사건 카드 (체스를 더 읽게 한다)

판에서 실제로 한 일이 카드가 된다. 확률이 없고, 판이 끝날 때 확정된다.

| 사건 | 카드 | 섬에서 |
| :--- | :--- | :--- |
| 캐슬링 | 성문 카드 | 성문 소품, 성벽 꾸미기 |
| 승급 | 왕관 씨앗 카드 | 호박 씨앗을 연다 |
| 앙파상 | 지나가던 손님 카드 | 바다 손님 하나가 섬에 들른다 |
| 한 수에 체크하며 잡기 | 번개 카드 | 공장 한 판 +1 |
| 세 수 연속 잡기 | 잔치 카드 | 상점 주문 하나가 두 배 |
| 체크메이트 | 깃발 카드 | 그 칸의 깃발, 축제 무대 |

- 사건은 이미 기록되고 있다. 캐슬링·승급·메이트는 `src/village/roster.js` 의 `replayGame` 이 센다.
- 앙파상·연속 잡기·체크 잡기는 수 목록에서 새로 센다.
- 사건 카드는 도감 옆 "사건 앨범"에 쌓이고 장수가 보인다. 합성하지 않는다.
- 효과는 그 판 끝 한 번이다. 모아 두는 소모 재료가 아니다.

### 3-2. 직무 배지 (같은 카드로 다른 일을 한다)

주민 카드에 판 사이에 배지 하나를 붙인다. 비용이 없고 언제든 바꾼다. 무작위 드롭이 아니다.

| 배지 | 들어가면 좋은 곳 | 효과 (시작값) |
| :--- | :--- | :--- |
| 농부 | 밭 | 그 주민의 영향권 안 밭 칸 +1 |
| 장인 | 풍차·빵집·공장 | 원료 1 절약 |
| 상인 | 상점 | 주문 보너스 +1 |
| 요리사 | 온천·식당 | 하트 +1 |

- 배지는 카드 등급을 바꾸지 않는다. 같은 미어캣도 농부와 상인으로 다르게 쓴다.
- 배지 칸은 등급에 따라 늘어난다. 일반 1개, 영웅 2개.

### 3-3. 씨앗 (작물을 여는 열쇠)

새 작물은 체스 사건으로 연다. 한 번 열면 계속 심는다. 씨앗을 태우지 않는다.

| 작물 | 여는 사건 |
| :--- | :--- |
| 밀, 당근 | 처음부터 |
| 딸기 | 나이트(캥거루)로 잡기 한 번 |
| 호박 | 승급 한 번 |
| 해바라기 | 캐슬링 한 번 |

### 3-4. 바다 손님 앨범 (나중 단계)

이미 만든 바다 생물 11종을 쓴다. 부두를 지은 섬에 판 끝마다 손님이 하나 들른다. 체스 드롭과 따로 센다. 사람 시험 뒤에 넣는다.

## 4. 농장 — 칸으로 일구는 밭

### 지금 상태

- 밭은 건물 하나이고 같은 건물은 두 채를 못 짓는다 (`buildBlocked`, `src/village/economy.js:229`).
- 판 끝에 곡물 `2 + output` 을 한 번에 낸다 (`src/village/economy.js:154`).
- 화면의 3×3 이삭은 곡물이 1 이상이면 모두 익은 색이 된다 (`src/village/islandScene.ts:282`). 칸마다 다르지 않다.
- 판 사이에 할 수 있는 것은 건물 놓기, 주민 옮기기, 쓰다듬기뿐이다. 장터는 자동으로 판다.

### 바꾸는 것

- **칸:** 밭의 3×3 이삭을 9칸 농장으로 바꾼다. 밭 레벨 0~3에 따라 3·5·7·9칸이 열린다. 레벨은 지금처럼 의뢰로 오른다.
- **작물 고르기:** 칸을 누르면 작물을 고른다. 고르지 않으면 지난 작물을 그대로 심는다. 처음에는 밀이다.
- **자람:** 판이 한 번 끝나면 자라고 수확된다. 실시간 타이머, 썩음, 물 주기는 없다.
- **돌봄:** 판 사이에 칸을 한 번 더 누르면 다음 수확 +1. 하지 않아도 손해가 없다.
- **특기 주민:** 동물마다 좋아하는 작물이 있다. 그 주민의 영향권이 닿는 칸에서 +1. 영향권 미리보기는 지금 것을 쓴다 (`src/VillageView.tsx`).

| 작물 | 좋아하는 주민 | 나오는 것 | 쓰는 곳 |
| :--- | :--- | :--- | :--- |
| 밀 | 미어캣 | 곡물 | 빵집, 상점 |
| 당근 | 캥거루 | 당근 | 온천의 간식(하트), 상점 |
| 딸기 | 판다 | 딸기 | 잼 공장, 상점 |
| 호박 | 코뿔소 | 호박 | 상점의 큰 주문, 축제 |
| 해바라기 | 사자·호랑이 | 씨앗기름 | 공장, 밤 등불 |

- 특정 동물이 없어도 모든 작물을 심을 수 있다. 특기는 보너스일 뿐이다 (섬 계획 §12 "특정 카드 요구" 금지).
- 창고는 작물마다 상한이 있고, 차면 그 칸만 쉰다. 버려지지 않는다.
- 9칸이 곡물 상한 20을 너무 빨리 채울 수 있다(추정). 그래서 칸은 레벨로 열고, `island_sim.mjs` 를 다시 돌려 페이스를 맞춘다.
- 모델: 작물 다섯 종은 코드로 그린다(지금 이삭처럼). 호박·해바라기만 모양이 필요하면 Flow → TRELLIS 로 만든다.

## 5. 경제 — 밭, 공장, 상점, 백화점

### 재화

| 재화 | 들어오는 곳 | 나가는 곳 |
| :--- | :--- | :--- |
| 도토리 | 판 결과 30/20/15, 상점 판매, 주문 보너스 | 건물, 업그레이드, 백화점 꾸미기 |
| 작물 5종 | 밭 칸 | 공장 원료, 상점 판매, 온천 |
| 가공품 (빵, 잼, 기름) | 빵집, 공장 | 상점 주문, 온천 |
| 하트 | MVP, 쉼터, 온천, 쓰다듬기 | 말 외형 단계 |
| 별가루 | 남는 희귀·영웅 카드 | 카드 선반, 배지 칸 |

새 화폐는 만들지 않는다. 사슬은 깊이 2를 넘기지 않는다(작물 → 가공품).

### 건물

기존 8종에 둘을 더한다.

| 건물 | 도토리 | 하는 일 | 상태 |
| :--- | ---: | :--- | :--- |
| 밭 | 20 | 칸 농장 | 바꿈 |
| 풍차 | 40 | 빵 원료 절약 | 있음 |
| 빵집 | 80 | 곡물 → 빵 | 있음 |
| **공장** | 100 | 딸기 → 잼, 해바라기 → 기름 | 신규 |
| **상점** (지금 장터) | 60 | 손으로 고르는 판매, 주민 주문 | 바꿈 |
| 온천 | 160 | 빵·당근 → 하트 | 있음 |
| 반딧불 발전소, 숲 쉼터, 축제 무대 | | | 있음 |
| **백화점** | 섬 완성 뒤 | 꾸미기·외형 상점 | 신규 |

### 상점과 주문 (미니 현실의 수요)

- 판이 끝날 때마다 주민 둘이 **주문**을 낸다. "빵 2개", "잼 1개와 당근 3개" 같은 것이다.
- 주문을 채우면 기본 가격에 보너스가 붙는다. 못 채워도 벌이 없고 다음 판에 새 주문이 나온다.
- 주문은 섬 번호와 판 수로 정한다. 다시 열어도 바뀌지 않는다.
- 주문 없이 그냥 팔 수도 있다. 판매량은 판당 3개로 시작한다. 돈이 너무 빨리 불어나지 않게 막는 장치다.
- 가격은 시간에 따라 오르내리지 않는다. 산 물건을 되팔 수 없다.
- 시작값: 곡물 2, 당근 2, 딸기 3, 호박 5, 빵 8, 잼 10, 기름 10 도토리. 주문 보너스 +1~3.

### 백화점

첫 섬을 완성하면 열린다. 도토리를 꾸미기에 쓰는 곳이다.

- 판다: 말 모자, 받침 무늬, 섬 소품, 밤 등불 색, 카드 테두리.
- 팔지 않는다: 체스 실력, 카드, 확률, 시간 단축.
- 처음에는 상점 화면 안의 매대로 시작한다. 사람이 재미있어하면 건물 모델을 만든다.

### 바꾸는 기존 규칙

- **라이벌 방문의 4시간 도토리:** 실제 시간으로 돈이 들어오는 유일한 곳이다 (`tickVillage`, `src/village/economy.js:320`). "체스가 시계"와 맞지 않는다. 판 끝에 한 번 들르는 손님으로 바꾸고, 선물은 꾸미기 소품으로 바꾼다.
- **건설 한 번에 하나:** 지금은 짓는 중인 건물이 있으면 다른 건물을 못 짓는다 (`buildBlocked`). 그대로 둔다. 한 판에 변화 하나라는 페이스의 축이다.

### 판당 대략 (추정)

| 시기 | 수입 | 쓸 곳 |
| :--- | :--- | :--- |
| 1~5판 | 판 결과 15~30 + 밀 판매 4~6 | 밭, 풍차, 상점 |
| 6~15판 | + 빵·당근 주문 10~20 | 빵집, 공장, 온천 |
| 16판~ | + 잼·호박 주문 20~30 | 무대, 발전소, 백화점 |

8개 건물 완성 중앙값은 지금 봇으로 20~23판이다. 작물과 주문이 붙으면 빨라질 수 있으므로, 같은 봇으로 다시 재서 20~26판 안에 둔다.

## 6. 판 사이 흐름

지금은 체크메이트 화면의 `새 게임` 버튼이 가장 앞에 있고, 섬은 알림으로만 보인다 (`src/App.tsx:334-340`). 섬을 건너뛰기 쉽다.

| 순서 | 화면 | 시간 |
| :--- | :--- | :--- |
| 1 | 결과 한 장: 승패, 확정 카드, 사건 카드, 보장 진행 | 5~10초 |
| 2 | 버튼 하나 **섬으로**. 수확이 칸마다 튀어 오름 | 5~8초 |
| 3 | 권하는 손 하나: 빈 칸 심기, 주민 옮기기, 주문 채우기 중 하나만 빛남 | 30~120초 |
| 4 | 다음 주문과 의뢰가 한 줄로 보임 | 5초 |
| 5 | 큰 버튼 **다음 판**. 의뢰 한 줄이 판 위에도 남음 | |

- 모든 화면은 건너뛸 수 있다. 아무것도 안 해도 섬은 지금처럼 자동으로 돌아간다.
- 1~3분은 목표이고 측정값이 아니다.

## 7. 중독성과 어두운 패턴의 경계

**경계 문장: 한 판을 끝내면 이득이 보이고, 쉬면 그대로 있다. 오지 않았다고 깎이지 않는다.**

| 넣는다 | 넣지 않는다 |
| :--- | :--- |
| 다음 목표가 보인다: 빈 칸, 주문, 의뢰, 사건 앨범 | 실시간 타이머, 작물 썩음, 시간 제한 주문 |
| 한 판의 결과가 섬에 남는다: 길, 나무, 칸, 건물 | 연속 접속 보상과 끊기면 벌 |
| 판 사이 손이 짧고 의미 있다 | 에너지, 판 수 제한 |
| 무작위는 공개한다: 드롭표와 보장 | 유료 재화, 숨은 확률, 재굴림 |
| 사건 카드는 확률 없이 확정 | 특정 카드가 없으면 막히는 진행 |
| 섬 완성 → 사진 → 새 섬 | 끝없는 숫자 성장, 푸시 알림 |

중도 이탈 규칙은 손실 공포가 아니라 "끝까지 둔 판이 카드가 된다"로 보여 준다. 확인창 문구도 잃는다보다 끝내면 받는다를 앞에 둔다.

## 8. 만드는 순서

| 단계 | 내용 | 끝나는 조건 |
| :--- | :--- | :--- |
| 0 | 남은 바다 작업: 마을 섬의 투명한 바다, 해 지는 시간 흐름 | 마을 섬에서 산호가 보임, 판 처음과 끝의 하늘이 다름 |
| 1 | 이어 하기: 수 목록 저장, 다시 열면 같은 판 | 10수 둔 뒤 새로고침하면 같은 판, 같은 차례. 섬 정산 결과가 새로고침 없는 판과 같음 |
| 2 | 판 주머니, 정산 영수증, 기권 버튼, `새 게임` 확인창 | 리셋 뒤 도감 장수 그대로. 기권 뒤 `games` +1. 정산을 두 번 돌려도 한 번만 지급 |
| **사람 시험 A** | 어른 2명, 어린이 1명 이상이 3판씩 | 기권과 확인창 문구를 이해하는지. 새로고침을 벌로 느끼는지 |
| 3 | 사건 카드 6종, 사건 앨범 | 캐슬링·승급 판에서 카드가 한 번만 나옴. 테스트 |
| 4 | 칸 농장, 작물 5종, 씨앗, 특기, 돌봄 | 봇 대국으로 8건물 중앙값 20~26판 |
| 5 | 판 사이 흐름: 결과 → 섬 → 다음 판 | 끝난 뒤 한 번 눌러 섬, 건너뛰면 3초 안에 판 |
| **사람 시험 B** | 같은 사람이 5판 | 섬에 30초 이상 머물고 칸을 직접 만지는지. 안 만지면 6으로 가지 않고 4·5를 고친다 |
| 6 | 공장, 상점 주문, 직무 배지 | 봇으로 도토리 흐름 확인: 판당 수입 범위, 무한 매매 없음 |
| 7 | 백화점 매대, 라이벌 방문을 판 기준으로 | 첫 섬 완성 뒤 도토리가 쓸 곳이 생김 |
| 8 | 바다 손님 앨범, 백화점 건물 모델 | 사람 시험 B를 통과한 뒤 |

### 1단계 결과 (2026-11-02)

- **저장:** 싱글 대국에서 수가 놓일 때마다, 그리고 무르기 뒤에 수 목록을 `wildcrown.resume.v1` 에 쓴다. 판이 끝나거나 새 판을 시작하면 지운다. 멀티, 대본 대국, 관전은 저장하지 않는다.
- **복원:** 다시 열면 수 목록을 새 심판에 다시 두고 같은 판 번호로 이어 간다. 무르기용 판 스냅샷도 수마다 다시 만든다. "지난 판을 이어서 둡니다" 알림이 6초 뜬다. 이어 하는 판에는 카드 미션 선택을 다시 띄우지 않는다.
- **묻지 않고 이어 간다.** 거절 버튼 대신 `새 게임` 을 누르면 된다. 2단계에서 새 게임 확인창이 붙는다.
- **확인:**
  - 규칙 테스트 4개를 추가했다(`test/resume.test.mjs`). 무작위 대국 40판의 위치·차례·섬 정산 결과가 같고, 캐슬링·앙파상·승급이 보존되며, 끝난 판과 잘못된 수는 이어 가지 않는다.
  - 브라우저 실제 대국(ego-browser, round-20): 16수 뒤 새로고침하니 같은 FEN·같은 판 번호로 돌아왔다. 이어서 104수로 끝냈더니 정산 사건이 한 번, 같은 판 번호로 났고 저장이 지워졌다. 오류는 없었다.
- **남은 것:** 휴대폰 실기기에서 탭이 죽은 뒤 복원은 재지 않았다.

### 2단계 결과 (2026-11-02)

- **주머니:** 잡은 카드는 `wildcrown.pouch.v1` 에 판 번호와 함께 들어간다. 판 중에 굴리는 확률과 보장은 "도감 + 주머니"를 기준으로 하므로, 끝나서 확정한 결과가 바로 지급하던 때와 같다. 이어 하는 판은 주머니를 그대로 쓴다. 다른 판 번호로 판이 시작되면 남은 주머니는 버린다.
- **확정:** 판이 끝나면(메이트·무승부·10수 이상 기권) 주머니를 도감에 넣는다. 위로 카드는 첫 카드 희귀 보장을 쓰지 않는다.
- **한 번만 정산:** 카드 도감과 섬이 각각 정산한 판 번호 20개를 기억한다. 같은 판의 끝이 두 번 와도 두 번째는 아무것도 하지 않는다. 계획에 있던 "정산 영수증"은 만들지 않았다. 두 정산이 같은 이벤트 안에서 이어서 돌기 때문에 그 사이에 탭이 닫힐 틈이 없다고 보았다.
- **기권 버튼과 확인창:** 판 중에 `새 게임`, `진영 바꾸기`, `기권` 을 누르면 확인창이 뜬다. 문구는 "끝까지 두면 카드를 받아요"를 먼저 쓴다. 내 수 10수 이상이면 `기권하고 카드 받기` 가 가장 앞에 나온다. 기권하면 "대국 끝 · 기권했어요" 판이 뜨고 섬 정산은 패배로 한다.
- **확인:**
  - 규칙 테스트 5개 추가(`test/pouch.test.mjs`). 전체 109개 통과.
  - 브라우저 실제 대국(round-22): 8수에 주머니 3장 → 새로고침 뒤에도 3장 유지 → 확인창 `계속 두기` 는 같은 판 → `새 판 시작` 은 주머니 폐기, 도감 0장 그대로 → 새 판 11수 뒤 기권하니 도감 3장, 카드 판 수 1, 섬 판 수 1 → 2수째 기권은 그냥 그만두기. 오류 없음.
  - 끝까지 둔 판(round-20): 새로고침 뒤 이어서 끝내니 위로 카드 1장이 확정되고 주머니와 이어 하기 저장이 지워졌다.
- **고친 버그:** 처음에는 새로고침하면 시작 신호가 먼저 나가 주머니를 지웠다. 이어 할 판이 있을 때는 시작 신호를 보내지 않게 했다.
- **남은 것:** 라이벌 대국을 고르면 진행 중인 판을 묻지 않고 바꾼다. 확인창은 사람이 읽어 보지 않았다(사람 시험 A).

## 9. LLM 협업 방식

한 모델이 짜고 같은 모델이 검사하면 같은 맹점이 남는다. 이번 라운드에서도 셋이 서로 다른 사실 오류를 냈다(§10). 그래서 단계마다 역할을 나눈다.

| 일 | 맡는 것 | 이유 |
| :--- | :--- | :--- |
| 구현, 테스트, 통합 | Claude | 저장소 전체 맥락과 실행 |
| 설계 갈림길 | agy·grok·codex 독립안 → Claude 가 저장소로 대조 | 이번 라운드 방식. 확인된 것만 채택 |
| 변경 검토 | codex 읽기 전용으로 diff 검토 | 파일을 직접 읽고 줄을 인용한다 |
| 페이스와 경제 | `island_sim.mjs` 봇 대국 (강·중·약) | 같은 규칙 코드로 판 수를 잰다 |
| 화면과 실제 대국 | ego-browser 대국 스크립트, 휴대폰 크기 확인 | 오류, 로딩, 화면 맞춤 |
| 재미 | 사람 시험 A·B | 봇과 모델은 재미를 판정하지 못한다 |

- 세 모델 라운드는 결정이 갈리는 곳에서만 돌린다: 1단계 시작 전(이어 하기 저장 형식), 4단계 전(작물 수치), 6단계 전(주문 수치).
- 모델의 수치와 사실은 저장소와 봇 측정으로만 채택한다. 셋이 같은 말을 해도 근거가 아니다.

## 11. 틀릴 수 있는 곳

1. 이어 하기가 실패하면 주머니 규칙이 그대로 벌이 된다. 1단계를 2단계보다 먼저 하는 이유다.
2. 작물 다섯, 가공품 셋, 주문이 어린이에게 많을 수 있다. 처음에는 밀·당근 둘과 주문 하나로 시작해 연다.
3. 판 사이 손이 숙제가 될 수 있다. 아무것도 안 해도 섬이 돌아가는 것이 안전장치다.
4. 상점 수입이 건설 페이스를 무너뜨릴 수 있다. 판매량 상한과 봇 재측정으로 막는다.
5. 10수 기권선은 근거가 없다. 사람 시험 A 에서 정한다.
6. 범위가 크다. 사람 시험 B 를 통과하지 못하면 6단계 이후를 멈춘다.

## 12. 사용자가 다시 정할 수 있는 것

1. 기권 확정선 10수.
2. 멀티플레이 카드 없음.
3. 백화점을 처음에는 화면 매대로 시작.
4. 라이벌 방문 도토리를 꾸미기 선물로 바꿈.
