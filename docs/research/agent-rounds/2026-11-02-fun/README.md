# 재미 설계 라운드 (2026-11-02)

결과 계획서: [재미 계획서](../../../plans/2026-11-02-fun-plan.md).

사용자 요청: 말 구분, 승부가 안 나는 AI, 상단 버튼 정리, 재미의 기준과 역전 찬스.
1~3 은 통합자가 같은 날 고쳤고, 세 모델은 4 를 설계했다.

| 파일 | 내용 |
| :--- | :--- |
| `BRIEF.md` | 공통 지시서 |
| `r1-claude.md` | 통합자 판정. 세 모델을 띄운 직후, 답을 읽기 전에 썼다 |
| `r1-agy.md` | agy. 파일 없이 브리핑만으로("도구를 쓰지 마라") |
| `r1-grok.md` | grok. `--prompt-file`, 계획 모드. 이번에는 답을 stdout 으로 냈다 |
| `r1-codex.md` | codex 읽기 전용. 저장소를 직접 읽었다. 최종 답만 옮겼다 |
| `ai_sim.mjs` | 예전 AI 와 새 AI 봇 대국. `node ai_sim.mjs normal greedy 10` |

## 판정

- 셋 다 "예전 AI 가 한 수만 봐서 승부가 안 난다"고 했다. 봇 대국으로 확인했다: 예전 AI 끼리 20판 중 14판 무승부.
- codex 의 저장소 인용 5개(라이벌 무작위 수, 되감기 중복 방지, 미션 주석, 플레이 계획서 3줄, 카드 원칙)는 모두 맞았다.
- 갈린 것: 지고 있을 때 AI 를 몰래 느슨하게 하는 고무줄. agy 찬성, grok 공개 성격으로만, codex 반대. 넣지 않기로 했다. 근거는 측정이 아니라 원칙(카드 계획 §2, 숙련자 신뢰)이며, 사람 시험 A 에서 다시 본다.
- 판 길이 목표가 5~7분 / 8~15분 / 10~20분으로 갈렸다. 정하지 않고 사람 측정으로 넘겼다.
- 지어낸 인용은 찾지 못했다. 외부 사례는 셋 다 "기억에 의존"이라고 적었다.

## 닿지 못한 것

사람 측정이 없다. 새 AI 는 봇과만 두었다.
