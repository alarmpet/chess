# r1-claude — 통합자 독립 판정 (셋의 답을 읽기 전에 씀, 2026-11-04)

## A. three.js 없이 되나
된다. three 는 「WebGL 을 쉽게 부르는 라이브러리」일 뿐이고, 이 게임의 요구(GLB 32개 로드·스켈레톤 애니메이션·그림자·물·외곽선·DOM UI)는 다음으로도 채워진다.

| 후보 | 요구 충족 | 비고(내 인상, 미확인은 표시) |
| :-- | :-- | :-- |
| Babylon.js | 됨. glTF 로더·스켈레톤·PBR·WebGPU 엔진 내장 | Apache-2.0(확인 필요). 번들이 three 보다 크다는 인상 — 재 보지 않았다 |
| PlayCanvas 엔진 | 됨. 에디터는 클라우드 서비스 | 엔진 MIT(확인 필요) |
| 순수 WebGL/WebGPU | 되지만 GLTF 로더·스킨·행렬을 손으로 다시 짠다 | 1인 개발에 비합리 |
| Godot 웹 내보내기 | 됨. Compatibility 렌더러. GDScript 로 전부 재작성, React UI 못 가져감 | chess.js 못 가져감(JS→GDScript 재구현 또는 JavaScriptBridge — 재 보지 않았다) |
| Unity 웹 | 됨. C#. 모바일 웹은 2급 | 라이선스 변동 이력 |
| Godot/Unity 네이티브 | 웹 포기 시 가장 좋음 | 스토어 네이티브 출시가 1급이 될 때만 |

## B. 장기 손익 (내 판단)
- three 에 남는 비용: (1) 월 릴리스로 r170 → 최신 올릴 때 깨지는 변경(특히 WebGPU/TSL 전환, `ShaderMaterial`·`onBeforeCompile` 못 간다는 것은 기획서 §4.2 가 이미 적음). (2) 에디터 부재 → Blender 가 채운다. (3) 6,300줄 단일 파일은 엔진이 아니라 우리 구조 문제 — 어느 엔진으로 가도 다시 쌓인다.
- 떠나는 비용: 13,710줄·테스트 135·절차 애니메이션 도구 재작성. GLB 125개는 가져간다. chess.js 는 JS 엔진에서만 그대로.
- LLM 협업: three/React/TS 는 학습 데이터가 많아 LLM 이 잘 쓴다는 **인상**. Godot 4 GDScript 는 3.x 와 섞여 LLM 이 틀리는 **인상**. 근거 없음.

## C. 이전 비용 추정
- 그대로 가는 것: GLB 125개(100%), 기획 문서, 파이썬 도구(TRELLIS·리그 — 엔진 무관), 게임 규칙 지식.
- 다시 쓰는 것: 장면·안무·카메라 6,300줄, 효과 1,269줄, 섬 장면, UI(React) 전부, 테스트 135개 중 규칙·경제 테스트는 언어만 바꾸면 되나 chess.js 의존 테스트는 심판 재구현 뒤에만.
- 추정: Godot 전면 이전은 「지금까지 쓴 시간의 60~80%」 — 근거는 줄 수 비율(13,710 중 규칙·경제 약 2,000줄만 로직 이식 가능)이고, 측정이 아니다.

## D. 조건부 결론
- **남는다**, 다음 셋이 모두 참인 동안: (1) 웹이 1급 배포 (2) 장면이 체스판+섬 규모 (3) 드로우콜 220 → ≤100 을 인스턴싱·머지로 줄여 내장 GPU 에서 p95 ≤ 33ms 를 맞춘다. (3)은 Phase 1 실측 과제 — `renderer.info.render.calls` 와 `tools/perf_probe.mjs` 로 1일.
- **떠난다(Godot)**, 다음 하나라도 참이면: (a) 스토어 네이티브 매출이 웹의 3배 이상이라는 자료가 나올 때 (b) (3) 을 2주 안에 못 맞출 때 (c) 멀티플레이가 실시간 동기(체스는 턴제라 해당 없음) 가 될 때.
- Babylon 으로의 「하이브리드 교체」는 three 를 떠날 이유가 (b) 성능일 때는 답이 아니다(둘 다 WebGL 위). WebGPU 가 필요할 때 three TSL 과 Babylon 을 **같은 장면으로 재서** 고른다.

## E. 틀릴 수 있는 곳
1. LLM 적합성은 전부 인상이다.
2. 「드로우콜을 three 에서 줄일 수 있다」는 아직 안 해 본 가설이다. `SkeletonUtils.clone` 32개는 인스턴싱이 어렵다.
3. 이전 비용 60~80% 는 줄 수 비례 추정이고, 실제로는 Godot 에디터가 안무·카메라 코드를 크게 줄일 수 있다.
