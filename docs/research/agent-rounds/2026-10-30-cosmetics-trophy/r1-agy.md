## 1. 사용자의 세 질문에 답

### (a) 내추럴로 시작해 복장·소품이 늘어나는 게 낫나
- **추천**: **기존 4단계 외형에 머리·목 '리지드 소품'만 단계적 해금 추가**.
- **이유**: 현재 48개 GLB는 표식·의상이 단일 메시에 결합되어 있어 벗기려면 전량 재제작해야 합니다. 소품 도구는 뼈대 없는 강체만 지원하므로 후드 같은 스킨드 의복은 엔진상 불가능하며, 신발은 발 뼈가 없어 장착 불가합니다. 헤드폰·선글라스 등 머리·목 리지드 소품만 툴 파이프라인에 즉시 부합합니다.
- **버릴 것**: 스킨드 의상(후드티 등), 신발(발 본 부재), 48개 GLB 재추출 방식의 '의상 벗기기'.

### (b) 이길 때마다 상대편 전리품을 뺏어 장착하는 구조
- **추천**: **PvE/AI 격파 시 상대 장착 소품 '카탈로그 해금(복제 획득)'**.
- **이유**: 현재 서버·계정이 없고 `localStorage`뿐이라 실시간 소유권 이전이 불가능하며 클라이언트 위변조에 무방비입니다. 1회 대국 내 포획 기물의 장식을 내 기물에 임시 복제 착용하거나, 로컬 승리 시 해당 소품을 도감에 해금하는 방식이 안전합니다.
- **버릴 것**: 상대 소유권 강탈(Zero-sum 삭제), 서버 없는 환경에서의 계정 간 소품 이전.

### (c) 랭킹 1·2·3등 무지개·금·은 아우라
- **추천**: **체스 받침대(Pedestal) 상단 림 발광 머티리얼 교체**.
- **이유**: 전신 파티클/메시 아우라는 기물 32개 렌더링 시 드로우콜과 연산 부담이 급증합니다. 받침대(`makePedestal`)는 캐시된 단일 형상이므로, Emissive 림 텍스처/머티리얼 3종(무지개·금·은)만 추가하면 드로우콜 증가를 0~1개 수준으로 억제할 수 있습니다.
- **버릴 것**: 전신 파티클 시스템, 포스트프로세싱 블룸 전면 적용, 서버 없는 실시간 글로벌 랭킹 연동.

## 2. 새 아이디어 (5개 이내)

1. **포획 문양 받침대 (Capture Pedestal Seal)**
   - *플레이어 경험*: 적 퀸/룩을 잡은 내 기물의 받침대 테두리에 황금빛 포획 인장이 새겨진다.
   - *체스 적합성*: 기물 교환이 핵심인 체스에서 전공(戰功)을 보드 위 위치와 함께 시각화.
   - *비용*: 모델 0개 (기존 LatheGeometry pedestal 머티리얼/텍스처 분기), 서버 불필요.
   - *규칙 충돌*: 없음 (§10-10 외형 전용, §2.2.4 식별 실루엣 유지).

2. **승급 티아라 즉시 안착 (Instant Promotion Tiara)**
   - *플레이어 경험*: 폰이 8열 도달 시 머리 소켓(`Head`)에 프로모션 전용 왕관이 즉시 씌워진다.
   - *체스 적합성*: 체스 고유 규칙인 폰 승급의 성취감을 극대화.
   - *비용*: 모델 1개 (`tools/make_prop.py` 4분 생성), 서버 불필요.
   - *규칙 충돌*: 없음 (§14.3 머리 슬롯, §14.0 자동 퀸/승급 선택 연계).

3. **체크메이트 챔피언 메달 (Checkmate Laurels)**
   - *플레이어 경험*: 체크메이트를 가한 마지막 기물의 목(`Neck`)에 승리 즉시 메달이 수여된다.
   - *체스 적합성*: 승패를 결정지은 MVP 기물을 명확히 기림.
   - *비용*: 모델 1개 (`tools/make_prop.py`), 서버 불필요.
   - *규칙 충돌*: 없음 (§12.3 Neck 소켓 `Chest` 본 부착, §14.3 비무기 장식).

4. **연승 불꽃 꼬리링 (Streak Tail Ring)**
   - *플레이어 경험*: AI 연승 달성 시 기물 꼬리 끝에 작은 발광 링이 장착된다.
   - *체스 적합성*: 킹·비숍의 역할 표식(머리)을 전혀 가리지 않고 숙련도를 과시.
   - *비용*: 모델 1개, 서버 불필요.
   - *규칙 충돌*: 없음 (`Tail` 본 실존, §2.2.4 역할 식별 안전).

5. **명국 박제 턴테이블 (Post-Game Showcase)**
   - *플레이어 경험*: 대국 승리 후 착용한 전리품 세트를 갖춘 MVP 기물이 3D 진열장에서 회전한다.
   - *체스 적합성*: 기보 복기 문화와 결합된 결과 감상 공간 제공.
   - *비용*: 모델 0개 (기존 씬 렌더링 재활용), 서버 불필요 (`localStorage` 저장).
   - *규칙 충돌*: 없음 (인게임 보드 외부 UI 연출).

## 4. 내 담당(agy)에서만 보이는 것

1. **후드·신발 장착의 기술적 불가능성**:
   - `biped_rig.py`에 `Foot` 본이 전혀 없어 신발 소켓 정의가 불가능합니다.
   - 후드티는 메시 변형(스킨드)이 필요한 의복인데, `make_prop.py` 파이프라인은 리깅 없는 강체(`inner.position` 고정)만 생성합니다. 의상 변경은 48개 베이스 모델 전면 재제작 외에는 불가능합니다.
2. **`makePedestal` 캐시를 통한 아우라 드로우콜 0 최적화**:
   - [wizardChessEngine.js](file:///D:/chess/.reports/consult-cosmetics-trophy/wizardChessEngine.js)의 `makePedestal`은 `LatheGeometry`와 머티리얼을 `pedestalCache`로 전역 관리합니다. 파티클 없이 받침대 림의 Emissive 텍스처/색상 교체만 적용하면 추가 드로우콜 없이 랭킹 아우라 연출이 가능합니다.
3. **`rebuildAllPieces`의 전체 재생성 비용**:
   - 장식 장착(`setCosmetics`) 시 64칸 전체를 지우고 `instantiatePiece`를 재호출하므로 대국 도중 실시간 장착 연출 시 프레임 드랍이 발생합니다.

## 6. 틀릴 수 있는 곳 셋과 스스로 가장 약하다고 보는 제안 하나

### 틀릴 수 있는 곳 셋
1. **드로우콜 측정 편차**: 실측치(140→152)가 말 위치 차이를 포함하므로, 32개 기물 풀 세팅 시 드로우콜 증가량이 예상치를 초과할 수 있음.
2. **소품 자동 안착 오차**: `computeSockets`의 `headBox.max.y` 기준 계산이 동물별 귀·뿔 높이 편차로 인해 공중에 뜨거나 파묻힐 수 있음.
3. **TRELLIS 비대칭 생성 한계**: 헤드폰 같은 얇고 대칭적인 구조물이 `make_prop.py` 단일 시드에서 왜곡될 수 있음(다중 시드 검증 필요).

### 가장 약하다고 보는 제안 하나
- **'연승 불꽃 꼬리링'**: `biped_rig.py`에 `Tail` 본은 있으나 현재 [wizardChessEngine.js](file:///D:/chess/.reports/consult-cosmetics-trophy/wizardChessEngine.js)의 `computeSockets`에는 꼬리 소켓 연산 로직이 전무하며, 종별(미어캣 vs 곰 등) 꼬리 길이 편차가 커 자동 배치 안정성이 가장 떨어집니다.
