# r1-claude — 통합자 독립 판정 (셋의 답을 읽기 전, 2026-10-27)

기획서 v0.2 를 쓴 것이 나이므로 "독립 설계안"은 곧 v0.2 다. 여기서는 **v0.2 에서 내가 스스로 약하다고 보는 곳**을 셋의 답을 보기 전에 적어 둔다. 셋이 이것을 찾으면 수렴이고, 다른 것을 찾으면 그게 이 라운드의 값어치다.

## 1. 틀릴 수 있는 곳 (내 순위)

### [C1] `rig_transfer.py` 공여 리그와 비율이 다른 종 — 코끼리·기린·코뿔소 (확신도 높음)
- chibi-rig.md 의 성공 사례는 전부 **개과·곰과·고양잇과 치비**(시바·늑대·판다·여우). `AnimalArmature` 46본은 Shiba/Husky/Fox 계열.
- 코끼리의 코, 기린의 목은 공여 뼈대에 대응 뼈가 **없다**. 가중치 이전은 "가장 가까운 면"이라 코와 목이 머리 뼈 하나에 통째로 붙어 뻣뻣하게 움직인다.
- farm 28본(소)이 덩치형에 낫다고 적었지만 **소에도 코·긴 목은 없다.** v0.2 의 "farm 28본 → UniRig → 절차" 폴백 순서는 맞지만, 기린은 처음부터 UniRig 또는 절차로 가는 게 맞을 수 있다.
- 재는 법: Phase 1 을 사자가 아니라 **기린으로** 돌리면 최악을 먼저 본다. 사자는 거의 확실히 된다.

### [C2] `MELEE_STANDOFF` 와 물기 공격 — 기획서가 빠뜨린 것 (확신도 높음)
- 엔진 2067행 `MELEE_STANDOFF = 0.36 // Optimal melee standoff (1.06 squares) so sword…` — **검 길이 기준 고정값**이다. Quaternius `Attack` 은 물기/앞발이라 사정거리가 훨씬 짧다. 접촉 비율(`contactClip`)만 맞춰도 **동물이 허공을 문다.**
- v0.2 매니페스트 `attackSync` 에 `standoff` 필드가 없다. 추가해야 한다. 이건 기획서의 **누락**이지 가설이 아니다.
- 재는 법: Phase 1 에서 사자 Attack 3프레임 렌더로 앞발 끝 거리 측정 → standoff 로.

### [C3] Phase 0 1주 — 낙관 (확신도 중간)
- r170→r185 + 모듈 분해 1차 + chess.js + Stockfish + CI + meshopt 재압축. 각각은 작지만 **r185 업그레이드가 기존 GLSL 셰이더 2개(561·700행 ShaderMaterial)와 PMREM 코드를 깰 가능성**이 있고, chess.js 는 보드 좌표계(엔진의 `r,c` vs 대수 표기)를 변환하는 층이 필요하다.
- 1주가 아니라 2주로 보는 게 맞을 수 있다. Phase 1 을 3일로 줄였으니 전체 기간은 비슷하다.

### [C4] 코브라 절차 애니메이션 — "엔진은 팩을 모른다" 원칙과 충돌 (확신도 중간)
- `rig: "procedural"` 을 만들면 `piece.ts` 에 재생기가 둘이 된다(믹서 / 절차). §6 커스텀 스킨이 어차피 절차를 쓰므로 공유되지만, **Attack 안무(`stepMove`)가 믹서 전제로 쓰여 있어** 절차 기물은 안무 코드에 분기가 생긴다. 앵무새(biped)로 바꾸면 분기가 사라진다. §10-2 에서 코브라를 추천했는데 **엔진 쪽 비용을 과소평가**했다.

### [C5] `bake_low.py` 16k·1024px — 재 보지 않음 (확신도 중간)
- study-game 이 8k·512 로 멈춘 이유는 레이스 70px 크기 때문이고, 체스는 기물이 화면 1/4 을 채운다. 2배가 충분한지 **4배(24k·2048)** 가 필요한지 모른다. 텍스처 2048 이면 종당 ~3MB → 팩 18MB 로 §4.4 첫 로딩 15MB 예산을 넘는다.

### [C6] "시간 변화 40수" — 재미인지 장식인지 (확신도 낮음)
- 체스 한 판이 20수에 끝나면 노을도 못 본다. 수가 아니라 **실시간**(10분 = 하루) 이 나을 수 있다. 사용자가 "빵빵하게"를 원하므로 유지하되 Phase 3 뒤로.

## 2. 하지 않을 것 (v0.2 에서 이미 뺀 것, 유지)
- WebGPU 즉시 전환 · 털 카드 · 물리 엔진(ammo/rapier — 파편은 기존 공유 VBO 로 충분) · 다중 뷰 콘셉트 · Blender Decimate.

## 3. 가장 약한 결정 하나
**§10-8 "tools/legend 를 복사한다".** study-game 의 스크립트는 그 저장소의 경로·`.reports/` 구조·`upgrade_runner` 큐에 묶여 있다. 복사하면 체스 쪽에서 돌릴 때 경로를 전부 고쳐야 하고, study-game 이 함정을 하나 더 고치면 체스는 못 받는다. 대안은 **study-game 에서 생성·굽기·리깅까지 하고 체스는 완성 GLB 만 받는다** — 즉 체스 저장소에는 `tools/` 가 없고 `public/packs/` 만 있다. 이게 더 단순하다. 셋이 뭐라 하는지 보고 정한다.

- E4 postprocessing r185 호환 — 확인 안 함. 깨져 있으면 three 내장 `EffectComposer` 로.
