## 이 판에서 바뀐 방법
- **1판의 약점:** 보조 에이전트가 뽑은 인용을 줄 단위로만 대조했고, 함수 전체는 읽지 않았다. 「우리 게임에 넣을 모양」에는 원본에 없는 안이 원본 근거처럼 섞여 있었다. 아래 「1판에서 틀린 것」 표가 그 목록이다.
- **2판에서 바꾼 것:**
  - 통합자가 **함수 전체를 직접 읽었다.** 근거는 모두 `파일:줄` 로 단다.
  - 설계의 각 항목에 출처를 붙인다. 원본 동작 그대로 쓰면 **[원본]**, 서버가 없는 우리 조건에 맞춰 바꾸면 **[바꿈]**, 우리가 정한 것이면 **[우리]**다.
- **실행은 하지 못했다.** 받은 저장소의 규칙 함수를 Node 로 불러 값을 재려 했지만, 받은 코드를 실행하는 일이라 권한 판정에서 막혔다. 우회하지 않았다. 사용자가 허락하면 harvest-hollow `shared/` 의 순수 함수를 격리된 하네스에서 불러 아래 표의 동작을 값으로 다시 확인할 수 있다.
  - Lua(SNKRX)와 C#(SS14)은 이 PC 에 실행기가 없다.
- 받은 곳은 `D:\tmp\oss-farm\` 이고, 빌드는 하지 않았다.

## 원본별 실제 동작 (직접 읽음)

### harvest-hollow — 주간 (G3 의 근거)
- **달력** (`shared/rules/calendar.js`)
  - `dayIndex(now, tz)` 는 지역 날짜를 UTC 로 읽어 1970-01-01 부터 센 일수다(`:34-37`).
  - `weekIndex = (day) => Math.floor((day + 3) / 7)`. 월요일에 시작하고, 1970-01-01 은 목요일이다(`:39-40`).
  - 규칙 안에서 `Date#getDay` 와 브라우저 시간대는 쓰지 않는다(`:4`). 시간대는 농장 값이고, 기본값은 서버 기기의 시간대다(`server/scheduler.js:15`).
  - 주의 월요일은 `weekStartDay = (w) => 7 * w - 3`(`coop.js:83`)이다.
- **주간 게시판** (`shared/rules/actions/folk.js`)
  - 상태: `folk = { w, n, posts, … }`. `w` 는 글이 속한 주이고 처음에는 -1 이다. `n` 은 지금까지 올린 글 수로, 난수 열쇠다(`:15-16`).
  - **할 일 판정:** `folkDue = … && state.farm.folk.w < weekOf(state, now)`(`:81-82`). 같다가 아니라 **작다**다. 시계를 되돌려도 다시 올리지 않는다.
  - **새 주 올리기 `postWeek`** (`:48-75`)
    1. 지난 글을 통째로 비운다(`:53`). 끝내지 못한 글은 주와 함께 사라진다(`:8`).
    2. `w` 를 이번 주로 바꾼다(`:54`).
    3. 후보 가운데 아직 안 고른 것에서 `ctx.rng('folk', n, 'npc')` 로 하나를 고른다(`:59-60`).
    4. 하나 고를 때마다 `n++` 하고(`:65`), 끝나면 `n` 을 저장한다(`:76`).
  - 밀린 주는 채우지 않는다. 몇 주를 건너뛰어도 올리는 것은 **지금 주 하나**다.
- **품평회** (`shared/rules/actions/fair.js`)
  - 상태: `fair.cur = { w, W, … , open }`. 주를 열 때 목표 W 를 그때 레벨로 **얼린다**(`:236-246`).
  - 닫기(`ceremony`)는 `open` 을 false 로 바꾸고 결과를 `last` 와 `unseen` 에 남긴다(`:294-296`). 두 사람이 따로 접속해도 결과를 놓치지 않게 하는 것이다.
  - `fairRoll`(`:317-324`)은 순서대로 두 가지를 한다. 지난 주가 열려 있고 마감이 지났으면 닫는다. 그다음 이번 주가 아직 없고 마감 전이면 연다.
  - 일요일 20시부터 월요일 0시 사이에는 열지 않는다(`:223`, `:323`).
- **누가 돌리나:** 시스템 행동 목록 `dueSystemActions`(`system.js`)를 서버가 돌린다.
  - 다음 할 일 시각에 타이머를 하나 건다(`server/scheduler.js:3-4`).
  - 부팅하면 밀린 일을 한 번에 돌린다(`:6`).
  - 노트북이 잠들었다 깨면 1초마다 확인한다(`:9-11`).
- **난수** (`shared/rules/rng.js`)
  - `hash32(...keys)` 는 murmur3 섞기다. `roll(seed, ...keys)` 는 0 이상 1 미만, `pick(seed, list, ...keys)` 는 목록에서 하나를 고른다(`:57-76`).
  - `shared/` 안에서는 `Math.random` 을 쓰지 않는다(`:4`).
  - 열쇠는 저장된 상태의 카운터와 이미 있는 id 로만 만든다. 시간과 행동 인자는 쓰지 않는다(`:6-10`).
  - 시드는 농장을 만들 때 호출자가 한 번 준다(`state.js:109`).

### SNKRX — 매대 (G4 의 근거)
- `set_cards(shop_level, …, first_call)` (`buy_screen.lua:343-367`)
  1. 세 칸을 모두 지운다(`:344-345`).
  2. 칸마다 `weighted_pick(level_to_shop_odds[레벨])` 로 등급을 고르고, 그 등급 목록에서 균등하게 하나를 고른다(`:351-355`). 칸끼리 겹칠 수 있다.
  3. 세 칸이 모두 공격하지 않는 유닛이면 다시 뽑는다(`:352`, `:357`).
  4. 처음 들어올 때 잠금이 저장돼 있으면 뽑은 것을 버리고 잠근 카드를 놓는다(`:358-361`).
- `weighted_pick` 은 0~합계 사이 실수 하나를 뽑아 누적으로 뺀다(`engine/math/random.lua:68-83`).
- 확률표 `level_to_shop_odds`: 1 {70,20,10,0} · 2 {50,30,15,5} · 3 {25,45,20,10} · 4 {10,25,45,20} · 5 {5,15,30,50}(`main.lua:1631-1636`).
- **레벨:** 라운드가 끝날 때(`Arena:transition`) 라운드 번호가 짝수이고 레벨이 5 미만이면 경험치 +1 이다. 필요 경험치는 3·4·5·6 이고 최대 레벨은 5 다(`arena.lua:979-991`).
  - 돈으로 경험치 사기(골드 5, `buy_screen.lua:820-847`), 레벨 내리기(골드 10, `:852-877`), 다시 굴리기(골드 2, `:994-1013`)도 있다.
- 잠금은 라운드가 끝날 때 잠겨 있지 않으면 지운다(`arena.lua:976`). 산 칸은 다음 `set_cards` 까지 빈 채로 남는다(`buy_screen.lua:1622`).

### Space Station 14 — 재고

### farming-game — 밤 정산과 주문 게시판
- `sleep()` 은 밤 하나에 난수 생성기 하나를 쓴다. 솔트는 `night:${year}:${season}:${day}` 라서 같은 시드면 같은 밤이 된다(`actions.ts:610-614`). 순서는 위 표에 적었다.
- 주문 게시판 `offerOrders`
  - 받지 않은 배달 주문 수를 세어 3 이 될 때까지만 새로 뽑는다(`market.ts:691-693`, `:700-707`).
  - 주석: 「일을 받아야 새 일이 나온다」(`:696-698`).
- 상점 `shopStock` 은 계절 씨앗과 상시 상품을 고정으로 늘어놓는다. 재고는 모두 `null`(무한)이다(`shop.ts:52`, `:61`, `:70`).
- 희귀 씨앗을 고르는 `caravanSeed` 는 `src` 어디에서도 부르지 않는다. 그런데 화면 문구(`src/shell/ui/ledger.ts:255`)는 희귀 씨앗이 상점에 들어온다고 말한다.
- 시드는 새 게임 때 한 번 `Math.random()` 으로 만든다(`src/renderer/main.ts:179`).
